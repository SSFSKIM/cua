# Gate #212: a save sheet completing across an intervention

- **Ticket:** [#212](https://github.com/SSFSKIM/cua/issues/212), "Verify unintended save-sheet completion across native
  intervention and report partial effects" (P1), with PR [#218](https://github.com/SSFSKIM/cua/pull/218). Gate of the
  macOS default switch (M5 pre-flight §6), task T8c.
- **State:** PR #218 re-cut on `feat/117-m5` and unit-proven. The hosted cell is prepared and has not run. **Open.**

## The report

From MAWS's dogfood (`l6-artifacts.md`, item 14), on cua's engine and host:

1. A native save sheet was open.
2. The agent called `setValue(saveAsNameTextField, <path>)`.
3. The call failed with `-10016 The user changed …`.
4. The sheet then closed, and a file with the default name was in Downloads. The reporter did not click Save.

The ticket's reading, which still holds: a plausible partial-action incident, not a proven engine-made Save. The
report has no per-call meta and no input trace, so who committed the sheet is not known. The engine's part was this:
the pre-action refusal and the stop between steps both answered with the same sentence. A null action interval was
the only hint, and it does not cover preparation (the AXFocused write, the focus fallback's click, route 3's
activation and its click). The answer could not say whether anything had happened.

## The change

The vendor's sentence still opens every userIntervened answer. One clause follows it:

| Where it stopped | Clause |
|---|---|
| The pre-action check, nothing done | `Nothing was done: the action was refused before its first step.` |
| The pre-action check, but the request ended a held activation | `The action was refused before its first step. What may have taken effect: the end of a held activation, which sends the app a deactivation. Nothing was undone.` |
| Between steps (the in-flight check) | `The action was stopped part-way. What may have taken effect: <steps>. Nothing was undone.` When no step is named: `Any step it had begun may have taken effect.` |

The steps (`InputEffect`, `native/engine/Sources/Engine/Intervention.swift`) are the ones the request reached:

- a scroll into view;
- route 3's activation, and its click at the activation point;
- the field's focus (the AXFocused write, or a WebKit field's caret or press, #324);
- the focus fallback's click;
- set_value's value write;
- the action's own input;
- a held activation ended by the request.

The input meta carries the same account as `interruption: {phase: "beforeAction" | "inFlight", effects: [...]}`. The
service forwards it as `cua/interruption` (reset per call). The secret wrapper withholds the engine's text, so it
repeats the account in the same fixed phrases. It never says "nothing was entered" next to a named step. The secret
counts as possibly entered once its write, or the action's own input, may have gone.

Commits:

- `d7e8ddbf3`: "macOS engine: a userIntervened answer tells a refusal from a stop part-way and names what may have
  taken effect (refs #212)". This is the engine. It rides on `engineVersion` 0.2.0, which T9 set for this pull request.
- `f3ec792a7`: "Secret wrapper and service: the engine's interruption account, in fixed phrases and as
  cua/interruption (refs #212)".
- `effafec35`: "native matrix: #212's save-sheet cell, intervention-save-sheet, prepared for the hosted pilot (refs
  #212)".

Under R3 this is not a departure. The vendor never stops an action in flight, and it waits out the debounce instead of
refusing. The intervention rows are judged against their own outcome, with the vendor's recorded beside them. The
harness matches the vendor's sentences as substrings (`USER_CHANGED`, `STILL_INTERACTING`), and the clause only
follows them.

## Hosted cell (prepared, not run)

The cell is `intervention-save-sheet` (`scripts/native-matrix/probe-plan.mjs`, `probe-run.mjs` `saveSheetAttempt`). It
is its own registered cell, not a row of the full matrix. Its row is `textedit/intervention.saveSheet`, in the
`intervention` section. TextEdit is in front, and the cell runs these steps:

1. super+n opens an untitled document, the sheet variant's typing cell types into it, and super+s opens the Save sheet.
   Each of these goes under the key guard.
2. The name field's index is kept from that observation (`ID: saveAsNameTextField`; the save sheet is the panel without
   `DontSaveButton`).
3. At the cell's time: `setValue(<name field>, "cua-212-intended")`. The probe's keystroke (`qz`, no Return) is aimed into
   TextEdit's front window, 10 ms after the call on the first attempt. Later attempts aim it 5 ms after the receipt they
   measured.
4. After a 2 s settle, the sheet is read again.
5. Whatever happened: the debounce is waited out, TextEdit is observed, Escape cancels the sheet, and the untitled
   document is closed with its Delete button. Nothing is ever saved.

The judgement:

- **cua passes** when the answer is the user-changed sentence with "The action was stopped part-way." and "may have
  taken effect", and the sheet is still open after the settle. The row keeps the answer, `cua/interruption`, whether the
  name was written, and the post's offset from the receipt.
- **Invalid, and retried:** a refusal before the action (the post came before the receipt), or a set_value that
  returned before the probe's event was seen. Three such attempts leave the row NO VERDICT.
- **A sheet gone after the act** fails the row, whatever the answer said.
- **The vendor's lane** never stops an action in flight. Its row records its answer and the sheet, and it is valid when
  the post fell inside the call.

The command runs on T10's harness: the loopback `hosted-macos` device, and the bundle built and approved in the run. The
cua lane is the gate's witness. The vendor lane is a record:

```
node scripts/native-matrix.mjs cell intervention-save-sheet --device hosted-macos --host cua --engine cua \
  --approved-runtime <the run's CUA_HOME> --approved-engine <the run's cua Engine.app> --sitting <id> --out <dir>
node scripts/native-matrix.mjs cell intervention-save-sheet --device hosted-macos --host vendor --engine vendor \
  --approved-runtime <the run's CUA_HOME> --approved-engine <the run's cua Engine.app> --sitting <id> --out <dir>
```

The dry run at `effafec35` walks the whole step sequence: three runs, three attempts each. With `--dry-run`, every
device step prints and none runs. The made-up acts never stop, so each row ends NO VERDICT, as it should.

**What it needs:**

- **Input Monitoring for the cua Engine bundle on the runner.** Without it, detection is off and the row is invalid
  ("intervention detection is off"). H0's TCC rows must include `kTCCServiceListenEvent` for the engine.
- **The probe's HID keystroke**, which H0 witnessed.
- **The Save sheet's identifiers, read on the runner's macOS.** `saveAsNameTextField` comes from #212's report, and the
  panel shape from the keep-or-delete cells. Neither has been read on a hosted Save sheet. The pilot's first run reads
  them: a "no Save sheet came up" precondition means the identifiers need adjusting, not that the gate failed.
- **The receipt window.** In front, with the field already focused, set_value's window between receipt and the write's
  check is short: tens of milliseconds by the code's steps, never measured. Three aimed attempts may not land inside it.
  If every run ends NO VERDICT for that reason, the cell needs a wider window (for example a probe burst that starts
  after the receipt), which is T10's call.
