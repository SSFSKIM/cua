# Gate #186: midSwitch's entered count

- **Ticket:** [#186](https://github.com/SSFSKIM/cua/issues/186), "Correct mid-switch cua/entered accounting so model
  resume does not duplicate a character" (P1). Gate of the macOS default switch (M5 pre-flight §6), task T8a.
- **State:** fixed on `feat/117-m5`, unit-proven. The runner witness is prepared and has not run. **Open.**

## The defect

`keyText` (`native/engine/Sources/Engine/Input.swift`) checks the input source before every event of a typed unit
(flags, key down, key up, flags restore) and after the last, and stops with `inputSourceChanged` at the first check
that sees a switch. It counted a unit only after all four events. The app inserts the unit's text on its key down, so a
switch seen before that unit's key up or its restore stopped the request with the unit already in the field but not
counted. Two of a unit's four check points fall there, which matches the record: one short in 3 of 6 Chrome and
Electron samples in M2b's hold 3, and in holds 2a and 2b (chrome 198/199, electron 188/189, chrome 180/181). A model
resuming from `cua/entered` typed that unit twice.

## The fix

A unit counts as entered once its key down is posted. The check points and the stop are unchanged. A switch seen
before a unit's key down still leaves it out, so `entered`, and the count in the sentence "The input source changed
after N of M characters were entered", equal the field's committed prefix. The counting unit stays the UTF-16 unit.

- Commit `8198c50a3`: "macOS engine: a keyed unit counts as entered once its key down is posted, so
  inputSourceChanged's count is the field's committed prefix (refs #186)". It rides on `engineVersion` 0.2.0, which T9
  set for this pull request.

## Runner witness (prepared, not run)

These are the matrix's three mid-switch rows, on a GitHub-hosted macOS runner. They are part of sitting C (pre-flight
§7), three runs a side:

- `textedit/midSwitch/typeText.long`
- `chrome/midSwitch/typeText.long`
- `electron/midSwitch/typeText.long`

Each row selects ABC and sends a long keyed `typeText` (`MID_SWITCH`, `scripts/native-matrix/unicode-plan.mjs`). The
probe switches to Korean 2-Set inside it. The row passes only when the request stops with the inputSourceChanged
sentence and the field holds exactly the text's first `cua/entered` units, by length and SHA-256
(`midSwitchAttempt`, `scripts/native-matrix/unicode-run.mjs`). A switch that lands outside the request's interval
makes the row invalid and is retried, never passed. No harness change was needed: the row already judges the count
against the field.

The smallest form is the `korean` cell, one field at a time, both lanes in one job. T10 provides the device, the run's
own install and the workflow:

```
node scripts/native-matrix.mjs cell korean --scene <textedit|chrome|electron> --device hosted-macos \
  --host cua --engine cua --approved-runtime <the run's CUA_HOME> --approved-engine <the run's cua Engine.app> \
  --sitting <id> --out <dir>
```

The cell runs every condition for the field. The mid-switch row is the gate's witness. The vendor's lane is not needed
for this gate. The judged form is sitting C's full matrix.

**What it needs:** T10's hosted harness (the loopback `hosted-macos` device, the bundle built and approved in the run,
the Korean 2-Set source selectable through TIS, which `docs/evidence/2026-11-18-paste-readback/` showed works on a
runner), at a head that carries `8198c50a3`.
