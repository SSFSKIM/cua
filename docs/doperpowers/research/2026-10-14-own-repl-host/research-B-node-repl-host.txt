QUESTION 2 — WIRE (three different transports; do not conflate them)
- cua -> runtime is ordinary newline-delimited JSON-RPC 2.0 over stdin/stdout, inherited through anchor and vendor launcher, NOT a native-pipe length frame. Each send is JSON.stringify(msg)+'\n'; readline parses each upstream line, drops non-JSON diagnostics (C/src/mcp/upstream.mjs:66-80,178-181). Both directions may carry requests/notifications/replies while a cell runs; stderr is separate.
- Session start: `{jsonrpc:"2.0",id:"cua-handshake",method:"initialize",params:<original client params>}`, then `{jsonrpc:"2.0",method:"notifications/initialized"}` after success. `tools/list` and `ping` standard. Handshake/tools records cached by runtime release, surface set, requested protocol version; a cache hit avoids launch until tools/call; capabilities (including elicitation) are still sent on actual launch (C/src/mcp/lazy-runtime.mjs:9-18,46-69,119-149,169-199). There is no separate upstream start-session command: connection + per-call IDs provide identity.
- Execute: `{jsonrpc:"2.0",id:<proxy counter>,method:"tools/call",params:{name:"js",arguments:{code,timeout_ms?,title?},_meta:{...clientMeta,callId,threadId:sessionId,sessionId,"x-codex-turn-metadata":{session_id,thread_id:sessionId,turn_id:taskId,call_id,model:<client name or mcp-client>},"codex/sandbox-state-meta":{permissionProfile,sandboxCwd}}}}`. Server-owned sandbox metadata replaces anything client-supplied. `js_reset` uses the same envelope with `arguments:{}` and keeps task identity. Exact producers C/src/mcp/server.mjs:111-123,215-229; sandbox.mjs:38-55. Observed upstream schemas/default 30 s: C/docs/evidence/m3-mcp-lifecycle.md:68-77; test schema C/test/fixtures/mcp-harness.mjs:9-14 (fixture, not independent vendor schema proof).
- Results: `{jsonrpc:"2.0",id,result:{content:[{type:"text",text}, {type:"image",data:<base64>,mimeType},...],isError?,_meta?,structuredContent?}}` or JSON-RPC `error:{code,message}`. Server corrects image MIME from magic, redacts token-bearing text/structured content, adds `_meta["cua/taskId"]`; error replies pass unchanged (C/src/mcp/server.mjs:222-228; surface.mjs:347-361; test/fixtures/mcp-harness.mjs:55-58).
- Cancellation `{method:"notifications/cancelled",params:{requestId,reason?}}` withdraws undispatched work, otherwise request ID is translated and notification forwarded immediately. Elicitation answers bypass JS queue. A running pinned cell ignores cancellation and eventually replies; timeout is in `arguments.timeout_ms`, not a separate cancel operation. C/src/mcp/server.mjs:327-346; observed C/docs/evidence/m3-mcp-lifecycle.md:55-80.
- End task is cua-local API, translated to `{method:"tools/call",params:{name:"turn_ended",arguments:{hook_event_name:"Stop",session_id:sessionId,turn_id:taskId},_meta:<same stamped metadata>}}`. Task machine waits for running work, rejects new/queued work when ending, requires acknowledgement, 5 s whole completion deadline; failure spends connection and tears down. `turn_ended` is private; `end_task`, `secrets_list`, `profiles_list`, `devices_list`, `devices_use` are NOT node_repl tools (C/src/mcp/server.mjs:145-151,290-324; task.mjs:1-13,192+; surface.mjs:25-64). Remote selection reroutes at cua's target layer, not a node_repl device protocol.
- Elicitation: runtime -> client `{jsonrpc:"2.0",id,method:"elicitation/create",params:{message,requestedSchema,_meta?}}`; client -> runtime `{jsonrpc:"2.0",id,result:{action:"accept"|"decline"|"cancel",content?,_meta?}}`. Cua tracks IDs; accept fills missing content with `{}` and missing meta with `{persist:"session"|"always"}` unless persist=none; never changes decline/cancel (server.mjs:340-370; surface.mjs:355-361). Trusted API `nodeRepl.createElicitation({message,requestedSchema?,meta?})` emits internal `{type:"elicit",id,exec_id,message,requested_schema,meta}` and fails if client lacks form support (T/node_repl.strings:22748-22814). This internal message is not MCP framing.
- Output is NOT established as a write-streaming MCP extension: embedded `nodeRepl.write(value,itemId?)` pushes `{kind:"write",text,item_id?}` into execution outputEvents (T/node_repl.strings:26243-26257); `emitImage` sends internal `{type:"emit_image",id,exec_id,image_url}` and waits for ack, with background op tracking (26259-26285). Trusted RPC replies carry output/content_items; exec_result carries accumulated output/content_items (25974-26005,22427+). cua forwards runtime notifications unchanged, including standard notifications/message (server.mjs:364-370; test/mcp-server.test.mjs:294-301), but no cua-specific write/emitImage streaming request set is implemented. Preserve ordered MCP content/results; do not invent a streaming requirement from the inner emit bridge.
- Secret markers are NOT a node_repl wire feature or source rewrite. Cua's trusted wrappers see RPC-decoded input and substitute an exact whole-field `{{secret:KEY}}` only for allowed sky methods or browser fill/AX input shapes; arbitrary JS/evaluate strings and substrings are not scanned. Sky input `{type:"execute",method,args:[input]}`; browser `{method:"execute"|"executeWithRecovery",params:{type,...}}`. Store lookup project-first/global-second is trusted-service work; malformed/reserved/unsupported references fail closed. Errors after substitution are replaced with fixed bounded diagnostics; no values/cause/vendor payload may cross (C/src/services/sky.mjs:6-26,69-128; browser.mjs:14-35,195-219; secret-input.mjs:26-31,56-92).
- 'host-trace' in cua is another separate channel: C/src/chrome/trace.mjs:4-26 reads only trace activation `<CUA_HOME>/state/host-trace.json` and appends diagnostic JSONL `{t,session?,name,kind,method,tabId?,target?,cdp?,paramKeys,...outcome}`. Vendor also has optional NODE_REPL_TRACE_META response-meta tracing with version/spans/{id,name,start_ms,duration_ms,status,attrs,parent_id?}, disabled unless enabled (T/node_repl.strings:25702-25828); cua's launch allowlist does not set it.

QUESTION 3 — CELL SEMANTICS AND TRUST BOUNDARY
- Persistent namespace, top-level await, redeclarable top-level bindings. Pinned implementation parses cells, carries prior exports through synthetic @prev modules, reconstructs declarations, evaluates SourceTextModule, commits bindings; completed bindings can survive an ordinary thrown error. This is more than wrapping every cell in an async IIFE (that loses lexical declarations). Dynamic await import works; top-level static imports are refused; process/node:process is denied to protect stdio. Embedded kernel evidence T/node_repl.strings:21127-21143,22036-22158,22314-22450. Public behaviour is documented in vendor tool-description strings:32074 and C/docs/evidence/m3-mcp-lifecycle.md:68-77; don't treat AST implementation itself as the compatibility requirement.
- First executable cell prepends NODE_REPL_JS_BANNER once per kernel; vendor banner is literally `await import("@oai/cua/tinyskyAlt");` (O/cua-repl/instructions/banner.js:1). That package's .../oai_js_cua/src/tinysky_alt/globals.js:1 reads nodeRepl.env.CUA_REPL_ENABLED_SURFACES, initializes chosen surface APIs and Reflect.set(globalThis,"cua",n), with initialize aliasing getState. create_tinysky_alt.js:1 additionally installs browser `agent` global when enabled. Bootstrap emits API docs via nodeRepl.write with named items cua.core / cua.browser.<id> / cua.state (create_bootstrap_emitter.js:1). Cell runtime provides immutable nodeRepl and tmpDir globals; nodeRepl includes cwd/homeDir/tmpDir/env/requestMeta/write/emitImage and rpc when trusted services enabled (T/node_repl.strings:22283-22313,26223-26287). Main context also has Buffer/URL/console/timers/fetch/crypto and common web globals, with eval/code generation strings+wasm disabled (21003-21051).
- default timeout is 30,000 ms. Timeout resets kernel, loses bindings/app/tab handles, next cell bootstraps anew. Ordinary MCP cancellation does not stop executing JS; only cell timeout does in normal server work (connection teardown can of course kill processes). cua serializes js_reset BEHIND JS, though direct raw node_repl reset preempts it; reset is not end_task and preserves task ID (C/docs/evidence/m3-mcp-lifecycle.md:55-82; C/test/mcp-server.test.mjs:266-280). Cua queues one work cell at a time (task.mjs:65-87,148-169), while elicitation/cancel remain live. Trusted withSuspendedTimeout sends suspend_timeout/resume_timeout around awaited work (T/node_repl.strings:23089-23111); retained native service's approval/startup use of it must remain functional, not count human wait as execution budget.
- Trusted worker is separate persistent Node process, full env, `handleRpc` import lazily cached per configured service. registerHooks resolves every file dependency by realpath under trustedCodeRoots; modules outside are rejected. nodeRepl privileged global is installed before importing handlers (T/node_repl.strings:25843-25973). Ordinary cells only see allowlisted nodeRepl.env and cannot call nativePipe; service process sees privileged APIs. JSON transport is a real semantic boundary: requests/results must serialize; error path returns ONLY error.message (String(error) for non-Error), never stack/cause/custom props/name. Kernel reconstructs a fresh Error from that string (25974-26009;22262-22275); C/docs/doperpowers/specs/2026-10-02-standalone-cua-design.md:507 independently records the measured rule. This is load-bearing for secret safety and BrowserServiceError codes (code is carried inside text), not free to 'improve' to rich Error serialization.
- Output/background semantics: runtime tracks un-awaited privileged promises, drains tracked work before ending the cell, runs after-submitted-code hooks after success AND error, merges trusted output/content items in execution order (T/node_repl.strings:22301-22309,22414-22445,25974-26029). cua browser service registers after-code hook {timeoutMs:12000,run} emitting browser notifications via emitContentItem; setup disposes prior browser runtime; turn-ended handler unregister returns a function (C/src/browser-service/index.mjs:173-213; test/browser-service/support/service-on-host.mjs:82-111). Host must support these hooks, not merely service.handleRpc.
- nativePipe contract is frozen {write,on,off,end}, on/off support data/close/error only, no destroy or end-event assumption; bytes cross worker/supervisor as base64 JSONL (spec:507; C/test/browser-service/support/service-on-host.mjs:85-96). Maintaining this privileged socket bridge preserves both scoped sandbox and MAWS same-user/ancestor checks. Direct socket opening from scoped trusted Node is not equivalent.
- Scoped (current macOS and browser-only Linux default): whole-disk reads subject to OS/TCC, writes only session run directory + valid absolute TMPDIR, no cell network. Default mode sends no metadata, vendor denies ordinary writes including temp and network. Disabled lifts filesystem/network restrictions, including writing trusted roots. Both kernel and trusted worker receive same sandbox policy; it does NOT hide secret files from model code. On Linux computer surface default is disabled to permit X11/AT-SPI helper; scoped browser route keeps supervisor nativePipe. Writable roots must not overlap trusted imports or CODEX_HOME, checked before launch; Linux scoped requires successful userns/bwrap preflight and refuses unavailable containment. C/src/runtime/sandbox.mjs:1-55,80-86,138-161; doctor.mjs:212-227; spec:141,503,533,545. Secret substitution is a trust-model feature, not protection against malicious authorized disk reads. Earlier Phase-B Keychain/broker arrangements are superseded by dated file-store decision (#66) and project tiers (#99); do not reimplement the obsolete broker.
