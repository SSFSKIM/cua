# Gate #189: pressKey r k under an engaged Korean input method

- **Ticket:** [#189](https://github.com/SSFSKIM/cua/issues/189), "Resolve Korean pressKey r/k expectations with an
  engaged input method" (P2). Gate of the macOS default switch (M5 pre-flight §6), task T8b.
- **State:** the expectation now follows ruling 1119, and the rule is unit-proven. No engine change. The runner witness
  is prepared and has not run. **Open.**

## The ruling

Ruling 1119 (#189): **pressKey sends physical keys, composed by the active input method.** With the source and the
layout observed after refocus, Korean 2-Set expects 가 and Latin expects "rk", in all three scenes. typeText keeps its
exact-text contract. If the vendor's lane composes differently, the row fails and cannot be declared.

This replaces the earlier expectation, `rk` under both sources. That expectation rested on the vendor's pid-posted keys
bypassing the input method (MAWS P4-B2). Hold 3 measured otherwise once the input method was engaged in the focused
field. Both engines composed 가 in every scene, with each target's source read as `2SetKorean` and its layout as
`2SetHangul` after the refocus:

| row | vendor run 1 | cua run 1 | cua run 2 |
|---|---|---|---|
| `<field>/latin/pressKey.rk` (textedit, chrome, electron) | length 2, exact | length 2, exact | length 2, exact |
| `<field>/korean/pressKey.rk` (textedit, chrome, electron) | length 1 | length 1 | length 1 |

Source: `docs/doperpowers/research/2026-10-18-own-native-engine/m2b/hold3/matrix/{vendor/run-1,cua/run-1,cua/run-2}/result.json`,
the rows' `outcome` and `meta.unicode.readings` (`korean:<field> post-refocus`: held, 2SetKorean, 2SetHangul). The
rows carry only the read-back's length and exactness, not the text. A length of 1 against `rk` is the single composed
syllable the ticket names. Those rows were judged against `rk` when recorded, so `summary` over hold 3 still lists them
as failed: a recorded `ok` is not re-judged.

## Runner witness (prepared, not run)

The six pressKey rows on a GitHub-hosted macOS runner, **both engines**, since the vendor's lane composing otherwise
fails the row:

- `textedit/latin/pressKey.rk`, `chrome/latin/pressKey.rk`, `electron/latin/pressKey.rk` (expect `rk`)
- `textedit/korean/pressKey.rk`, `chrome/korean/pressKey.rk`, `electron/korean/pressKey.rk` (expect `가`)

Each Korean row has a precondition reading in `meta.unicode.readings`: `korean:<field> post-refocus` with `held: true`,
`current: com.apple.inputmethod.Korean.2SetKorean`, `layout: com.apple.keylayout.2SetHangul`.

The rows are part of sitting C, three runs a side. The smallest form is the `korean` cell, one field at a time, both
lanes in one job. T10 provides the device, the run's own install and the workflow:

```
node scripts/native-matrix.mjs cell korean --scene <textedit|chrome|electron> --device hosted-macos \
  --host vendor --engine vendor --approved-runtime <the run's CUA_HOME> --approved-engine <the run's cua Engine.app> \
  --sitting <id> --out <dir>/vendor
node scripts/native-matrix.mjs cell korean --scene <textedit|chrome|electron> --device hosted-macos \
  --host cua --engine cua --approved-runtime <the run's CUA_HOME> --approved-engine <the run's cua Engine.app> \
  --sitting <id> --out <dir>/cua
```

The judged form is sitting C's full matrix and `summary`.

**What it needs:**

- T10's hosted harness: the loopback `hosted-macos` device, the bundle built and approved in the run, Chrome for
  Testing and the Electron fixture.
- Korean 2-Set selectable through TIS. `docs/evidence/2026-11-18-paste-readback/` showed that selection works on a
  runner.
- Not yet shown on a runner: that the refocus engages 2-Set's own layout (2SetHangul). If it never does, the Korean
  rows stay invalid, which is NO VERDICT, never a pass. That would be T10's harness question, not this gate's.

## Closing condition (open)

The pre-flight's condition (§6) is that "the Korean rows … are valid and judged". For this gate that means:

- every valid cua sample of the six rows passes: `rk` under Latin, `가` under Korean;
- each Korean sample counts only with its post-refocus reading held;
- the vendor's valid samples agree, which `summary` enforces;
- no row is left with no verdict.

A missing or invalid sample does not count toward closing. After a pass, record the run's URL and the row counts here,
then close the ticket.
