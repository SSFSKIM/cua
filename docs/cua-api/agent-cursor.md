While you act in an app, a cursor labelled with this session's name shows the user where each action lands, unless the user has turned it off, and fades a few seconds after your last action. Your actions do not wait for it, it is not the user's pointer, and your screenshots do not show it.

A web page in a Chromium-based app (Chrome, Electron apps) that is in the background does not take a pointer: unless this Mac is a dedicated desktop, a left click, double click or drag there is refused with "<App>'s web page does not accept a background click; bring <App> forward or use a dedicated desktop", and nothing is sent. A plain click there goes through the clicked element's own accessibility action instead when it has one, so prefer clicking such an element by its index. A click or drag that fails with `clickUnconfirmed` was sent but may only have activated the window: observe the app before any retry.
