A click, scroll or drag at coordinates outside the screenshot they came from fails with `pointOutsideScreenshot` and nothing is sent: give a point inside it, from 0 to its width less one across and from 0 to its height less one down, in its pixels. So a drag cannot end outside the app's window, on another app or the desktop. A scroll succeeds only once what is at its point was seen to move, or when that was already scrolled as far as it goes that way, in which case the result's text says so. Otherwise it fails with `scrollUnconfirmed`: the scroll was sent but nothing was seen to move, so observe the app (a new screenshot or `getAXState()`) before scrolling again. A Show Menu (`performSecondaryAction` with "Show Menu") succeeds only once a menu was seen to open. Otherwise it fails with `menuUnconfirmed`: the action was sent but no menu was seen within 1 s, and the app may have shown a menu of its own that accessibility does not expose (a web page's own menu, which a screenshot shows) or ignored the request, so observe the app before any retry. A Show Menu that succeeds means a menu appeared, not which one: if something else opens a menu in the same window within that second, its success can be that menu's, so check what the next observation shows before choosing an item. A `setValue` whose value was sent and accepted but whose field could not be found again afterwards fails with `valueUnconfirmed`: the value may have been entered, so observe the app before any retry. Within a second after a click in the same app, a `setValue` whose field then reads another value, or whose caret moves off the end of the new value (as a click the app takes in late moves it), also fails with `valueUnconfirmed`. Unless this Mac is a dedicated desktop, a `setValue` on a text field of a web page in a Chromium-based app in the background, when the field does not already have keyboard focus, sets the value without a click and then reads it back: it succeeds only once the field reads the new value, and otherwise fails with `valueUnconfirmed`, as it always does there for a `{{secret:…}}` or a password field, whose value is never read back, so observe the field before any retry. The field becomes the focused element of the page, but the page gets no focus or blur event for it, so anything a page does only on focus, such as opening a list of suggestions, does not happen.
