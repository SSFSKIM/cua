# cua's own macOS native engine (#117; child 4 of #114)

## Purpose

On macOS, cua's computer surface (`cua.getApp(...)`, `getAXState`, `click`, `typeText` and the rest of the window API the model learns from `docs/cua-api/core.md`) is answered by OpenAI's native helper, `Codex Computer Use.app` from the pinned `@oai/sky` package: it reads the accessibility tree, numbers the elements, delivers input, captures the window, and holds the Accessibility and Screen Recording permissions the user granted. Because that helper accepts only the vendor's `node_repl` as a socket peer, macOS computer sessions are also the last sessions still served by the vendor's REPL host instead of cua's own (#116). After this work, cua's own engine, `cua Engine.app`, answers the same API behind the same contract, cua's own host serves every session on every platform, and `cua install` on macOS stops downloading the vendor runtime archive altogether.

Three things become observable that are not today:

- **Nothing of the vendor runs.** `ps` during a session shows `cua-engine`, cua's Node and no `SkyComputerUseService`, `node_repl` or vendor Node started by cua. `cua doctor` shows cua's engine, its build and signature, and the permissions granted to it.
- **A driven app stays where it is.** Clicking a button in a background app does not bring that app's window to the front or take the keyboard focus from the window the user is working in, and the user typing in their own window does not stop the agent. Today the vendor's click path activates the app, which the owner experiences as windows jumping forward (#162's investigation).
- **The same speed or better, measured.** Every operation of the native baseline (`docs/evidence/2026-10-14-native-baseline/`) is answered within the no-regression rule, and the three points the owner named (speed, finding elements, not interfering) are recorded against the vendor's engine on the same machine before the default changes.

How to see it: on the mini, with the plugin at the release this work ships, run a session that binds TextEdit, keep a Finder window in front, and ask for a click in the TextEdit document. The Finder window stays in front and keeps the keyboard, the click lands, and `cua doctor` names `cua Engine.app` as the engine. The vendor engine stays selectable with `CUA_NATIVE_ENGINE=vendor` until M6 retires it.

Terms used below:

- **Engine**: the native process that touches the Accessibility API, input and capture. The vendor's is `SkyComputerUseService` inside `Codex Computer Use.app`; cua's is `cua-engine` inside `cua Engine.app`.
- **Service**: the JavaScript that runs in the trusted worker of the REPL host and talks to the engine. - **Skyshot**: the vendor's name for one observation of an app: its key window's accessibility text, optionally a screenshot. Kept as the name of the engine's observation result.
- **Scene**: one harness-owned window in one app family, used by the verification system (defined under "Verification system").
- **Lineage**: the engine's per-connection, per-app numbering of elements, in which an index keeps meaning across observations until the lineage ends.

## Design

### The contract kept, and what changes behind it

The facade's contract with the service does not change: `setup` returns `{target: "mac", methods: [the 11 names]}` and `execute {method, args}` returns what each method returns today (`R/A-contract.md` §1.2–1.4). The trusted wrapper `src/services/sky.mjs` keeps its pinned eligible shapes for secret substitution and its value-free error classification; the vendor module it delegates to is replaced by cua's service, selected by the launcher, and cua's service raises errors of the same class names and `errorName` values (`SkyComputerUseError`, `SkyComputerUseTransportError`) so the wrapper's classification needs no change. Error sentences the model sees are kept where cua's harnesses, acceptance scripts or the first-call document depend on them (`noWindowsAvailable`, `timeoutReached`, the `userIntervened` and `screenLocked` sentences, `The element ID is no longer valid…`, `<n> is an invalid element ID`, the select and set-value refusals, `Computer Use was not approved to use <app>`, the forbidden-app sentence); elsewhere they are cua's own and bounded.

What changes behind it: the engine process, the socket it listens on, who may connect, where approval memory lives, and which REPL host runs the session.

### The engine: `cua Engine.app`

**One Swift program, Apple frameworks only.** `native/engine/` is a Swift 6 package (`swift build -c release --scratch-path <under $CUA_HOME>`) producing the executable `cua-engine`, assembled into `cua Engine.app` (`LSUIElement`, hardened runtime, bundle id `io.github.ssfskim.cua.engine`, minimum macOS 14). It links ApplicationServices (the Accessibility API), CoreGraphics (events, window lists), ScreenCaptureKit (capture), AppKit (`NSWorkspace`, `NSRunningApplication`, `NSPasteboard`), Carbon's Text Input Sources (`TISCopyCurrentKeyboardInputSource`) and Foundation. No package dependencies: the owner's ruling bars unvetted third-party code, and Swift against Apple's frameworks needs none, where Rust would need binding crates. Apple SPI (private functions of SkyLight or CoreGraphics), where "Input" below needs it, is resolved with `dlsym` at run time and feature-detected, never a dependency. `engineVersion` is the package's version and `build` is the hash of the `native/engine/` source tree plus the assembling script, so two bundles with the same `build` are the same program.

**Process model: one engine per login session, launched on demand, resident.** The service launches the bundle through the own host's existing `nodeRepl.launchServices.openApplication({applicationPath})` relay (`src/repl-host/launch-services.mjs`), which M1 changes to run `/usr/bin/open -g -a <path>` (`-g`: launch in the background, so the engine's own launch never takes the user's focus; M0 probes whether `open` without it would). LaunchServices is then the engine's parent and TCC attributes the Accessibility and Screen Recording grants to the bundle, not to Node (the vendor's arrangement; Apple's guidance on responsible processes in `C-macos-prior-art.md` §6). The engine stays resident across sessions, as the vendor's does, and exits on a `shutdown` request or when the login session ends. `shutdown` is sent only by `cua install` when it replaces a bundle of the same version and by `cua engine stop`, and the engine refuses it while another connection is open (`{error: "busy"}`); **a service never shuts down an engine it did not launch.** On a version mismatch the service fails the connection with a diagnostic naming `cua install`. The reason is the mini, where the resident agent's checkout and the parity clone each build their own engine: a service that "fixed" a mismatch by shutting the other's engine down would restart the other session's lineages mid-task, possibly mid-drag with a button held. The alternative process model, one engine per connection as a child of the trusted worker, would give peer authentication for free but makes TCC attribution depend on the process tree and re-prompts after rebuilds and relaunch heuristics; rejected.

**Socket and peer check.** The engine listens on `engine.sock` beside its own bundle, `$CUA_HOME/engine/<engineVersion>/engine.sock`: the engine derives the path from `Bundle.main.bundlePath`, the service from `CUA_ENGINE_APP`, so no argument crosses the LaunchServices launch (`open` passes no environment, and an already-running instance gets no new arguments), and engines of different versions coexist. The directory is created with mode 0700. `CUA_ENGINE_SOCKET` overrides the path only when a harness runs the engine executable directly rather than through the relay. On accept the engine reads the peer's uid with `getpeereid(2)` and closes any connection from another uid; the kernel's seatbelt profile denies the engine directory's sockets to cells (the unix-socket deny pattern that already exists in `src/sandbox/seatbelt.mjs`), so under the scoped sandbox only the trusted worker reaches the engine; and the engine itself refuses the forbidden list (system security processes and password managers, "The service" below) on `resolve_app` and every app-scoped request, whoever the client is. That is the whole peer policy. The threat model is the owner's own account, where an unsigned Node cannot carry a code-signing requirement anyway (`C-macos-prior-art.md` §6, "Authenticating a local Node client"); the vendor's ancestry check is what forced the vendor host on cua and is not reproduced. What remains exposed: any process of the owner's uid outside the sandbox, including a cell under `CUA_SHIM_SANDBOX=disabled` or the agent's own shell, can connect and observe or drive any non-forbidden app without an approval. That exposure is recorded as a decision for the owner to accept (Decision Log entry 3).

**Protocol: the facade's vocabulary, one layer down.** JSON-RPC 2.0, each frame a 4-byte little-endian length then UTF-8 JSON, 8 MiB maximum each way, one request in flight per connection, as the vendor's transport (`R/A-contract.md` §2.2). Methods: `ping {clientApiVersion}` → `{serverApiVersion, engineVersion, build}` with `serverApiVersion = "cua-engine-1"`; `execute {method, args, deadlineUnixMilliseconds, lineage?}` → the method's result or a JSON-RPC error `{code, message}` using the vendor's code numbers for the conditions cua maps (`R/A-contract.md` §1.5) and `-10005` with a bounded sentence otherwise; `status` → the engine's permissions and identity; `shutdown`. `execute.method` is one of the facade's 11 snake_case methods with the facade's argument shapes (`R/A-contract.md` §1.4, input column) plus two engine-only methods, `resolve_app {app}` and `get_app_state` returning a `Skyshot` tree instead of text. So the service translates nothing: it adds policy, approval, rendering and diffing around a request it otherwise forwards. The vendor's own IPC vocabulary (`ComputerUseIPC*Request`, the `{_0: …}` enum encodings) is not adopted: the earlier reason for it, one JS client for both engines, was false, since cua's client can never reach the vendor helper (its peer check), and the vendor client would have to be impersonated to reach cua's (Decision Log entry 2).

**Observation (skyshot).** `get_app_state {app, disableDiff?, includeScreenshot?, outputDirectory}` observes the app's key window (its `AXFocusedWindow`, else `AXMainWindow`; none → error `noWindowsAvailable`). The engine walks that window's accessibility tree depth-first in preorder (the order the text prints) with `AXUIElementCopyMultipleAttributeValues` fetching, per element in one call, role, subrole, role description, title, description, value, identifier, enabled, focused, selected, position, size and children, then `AXUIElementCopyActionNames`, and `AXUIElementGetPid` for every element, because sheets, open and save panels and some menus are served by another process (TextEdit's Open panel is; the baseline's `setup.newDocument` clicks its button) and input must be posted to the element's owner, not the app. The messaging timeout is set to 1 s on every element it touches (timeouts set on the application element do not reach its descendants), and a whole observation has its own 10 s traversal deadline apart from the request's 120 s: a hung app yields a truncated tree with the marker, not a stall. Chromium and Electron apps get `AXManualAccessibility` and `AXEnhancedUserInterface` set once per process so their web content exposes a tree (without it a browser page is a single group), and the first observation after enabling waits up to 1 s for the `AXWebArea` to populate. The vendor sets the same two attributes and, in addition, flips a global VoiceOver preference so that apps which check it expose their trees (`R/E-helper-catalogue.md` §2); cua does not touch that global setting, since it is visible to every app on the machine, unless M0's probe shows a scene family that exposes nothing without it, in which case the owner decides. The vendor also reads subtrees through a private batched hierarchy call with array caps and string truncation; cua's per-element batched fetch is the public route, and M0 measures whether it meets the vendor's medians before the recovered private call is considered as a route. Caps are explicit and each has a marker in the text: 40 levels (the vendor's `Max depth exceeded`), a node budget of 4,000 after which remaining subtrees are omitted and counted in `truncated`, and 10,000 characters per value, cut with a `[truncated]` suffix, so no single text view can exceed the 8 MiB frame. `valueMarkdown`, the Markdown rendering of an attributed value (headings, emphasis; the vendor renders them so `selectText` can quote them), is fetched only for text elements whose plain value is at most 2,000 characters, because the parameterized attributed-string fetch is the likely cost centre; M0 measures it. The result is a JSON tree (`Skyshot` in Interfaces), not text: **rendering to the model's text happens in the service.** The split is the point of the design: element handles (`AXUIElementRef`) cannot leave the process, so index assignment and re-resolution must live in the engine, while the grammar, pruning and diffing are pure functions that the service can run against recorded trees and the vendor's recorded text, which is how the grammar is pinned (goldens, under "Verification system"). Linux already renders client-side (`src/cua-api/linux-accessibility-tree.mjs`), so both platforms end up with the renderer where it can be tested.

**Indexes and handles.** Per (connection, app) the engine keeps a lineage: an id, a table from index to element handle plus the attributes that identify it (role, identifier, title, its path of child positions, its owning pid). On every observation, an element whose handle is equal (`CFEqual`) to one already in the lineage keeps its index; a new element takes the next unused index; a vanished element's index is retired, never reused in that lineage. An action naming an index resolves the handle; if the app reports it invalid, the engine re-fetches by walking the current tree for the one element matching the stored identification, returns `The element ID is no longer valid. Try to get the on-screen content again…` when none matches and the ambiguity sentence when several do. Every `Skyshot` carries its `lineage` id and every action names the lineage its index came from; the service keeps the lineage of the last observation per app and refuses, with the same "no longer valid" sentence, an index from another lineage, so a reconnect or a relaunched engine can never resolve a stale index to a different element. This is the vendor's observable behaviour (`R/A-contract.md` §3.3; its mechanism from `R/F-helper-logic.md`, M0), which the first-call document and the model's habits rely on.

**Screenshot.** When asked, a JPEG of the key window through ScreenCaptureKit (`SCContentFilter(desktopIndependentWindow:)`, `SCScreenshotManager.captureImage`), scaled to points (the baseline's 1172 × 976 for a window on a 2× display), quality 0.8, written with mode 0600 into `outputDirectory` (the session's run directory, which the kernel's sandbox lets the cell read) and returned as a `file:` URL, as the vendor returns it (`R/A-contract.md` §3.7). `CGWindowListCreateImage` is deprecated since macOS 15 and is not a fallback. Screen Recording's periodic re-confirmation on macOS 15 and later applies to any app without Apple's capture entitlement; the vendor's helper has none either, so this is parity, not a regression.

**App resolution and launch.** `resolve_app {app}` and every app-scoped method accept a bundle id, a display name or a path. Running regular apps match first; otherwise LaunchServices (`NSWorkspace.urlForApplication(withBundleIdentifier:)`, and for a name the `.app` of that name or localized name in `/Applications`, `/System/Applications`, `~/Applications` and `/System/Library/CoreServices`), with `ambiguousApp` when more than one matches and `invalidApp` when none. An app that is not running is launched without activation (`NSWorkspace.openApplication(at:configuration:)` with `activates = false`) and the observation waits up to 5 s for a window, then fails `timeoutReached` as the vendor does; the baseline's `bind.getApp.retry` row exists for exactly that path. `list_apps` returns every running regular app plus the apps this engine has resolved before, from its own usage store (`$CUA_HOME/engine/usage.json`: bundle id, last used, use count), so the vendor's `lastUsedDate` and `useCount` fields have cua's meaning; the bound identity returned to the facade is the app's path, as the vendor binds (`R/A-contract.md` §7).

### Input

Every input request names the app and either an element index or window coordinates. The rule that produces "not interfering": **the engine never activates an app on its own**, and input is posted to the process that owns the target element (`AXUIElementGetPid`), which for a sheet or an open panel is not the app. The routes, in order of preference:

1. **Accessibility actions** for element-targeted requests when the element advertises the action: `AXPress` for a single left click, `AXShowMenu` for a right click, `AXIncrement`/`AXDecrement`, the element's own secondary actions for `performSecondaryAction`, `AXValue` for `setValue` when settable, `AXSelectedTextRange` for `selectText`. These reach the element without events and need no focus.
2. **Public events posted to the owning process** (`CGEventPostToPid`, events created from a private event source, `CGEventSourceCreate(.privateState)`, so they never count as the user's input) for everything else: coordinate clicks, multi-clicks, drags, scroll wheel, key presses and typed text. The event's location is the window point; the window number field is set so the app's event routing finds the right window.
3. **Apple SPI**: the SkyLight posting function that carries a window-local authentication field, together with the active-state events that make AppKit treat the target window as if it were active for the duration of the click (the technique `C-macos-prior-art.md` §4 describes), resolved by `dlsym` with feature detection. The vendor's own names for this are `SyntheticAppFocusEnforcer`, which makes the target app believe it is active and focused while the user's app stays frontmost, and `SystemFocusStealPreventer`, which watches key-focus notifications and hands stolen focus back (`R/E-helper-catalogue.md` §3); their functions are the soft-linked ones tier 2 recovers. This route exists for the case M0 is expected to find: AppKit activating an app itself on a mouse-down delivered to a non-key window (an inference the spike's first probe decides), and Chromium dropping pid-posted pointer events. cua's choice of names is recorded in `sky-behaviour.md` with the evidence; absent symbol or failure → route 4.
4. **Foreground assist**, bounded and reported: activate the app, post, then restore the previously frontmost app and its key window. The result's meta (`cua/inputRoute: 4`) lets the harness count it, and the non-interference metric counts it as a failure for that action. It exists so a canvas app still works; it is not a route the engine chooses silently.

Which route each scene family lands on is decided by measurement in M0, not assumed. The baseline's `super+w` and `super+n` prove nothing about background delivery: the harness sent them while TextEdit was frontmost (the #162 key guard). Every result carries `cua/inputRoute` (1–4) so the matrices can see what carried each action.

**Keys** (`pressKey`): the vendor's xdotool-style grammar with aliases (`super`, `Control`/`Ctrl`, `Alt`, `Shift`, `KP_0`, `Return`, …; `R/A-contract.md` §7) parsed into virtual key codes through the current keyboard layout, modifier flags set on the events, every held modifier released after.

**Text** (`typeText`): the engine reads the active input source (`TISCopyCurrentKeyboardInputSource`) and routes by (app, input source). With a Latin source active, Unicode keyboard events (`CGEventKeyboardSetUnicodeString`) in chunks of at most 20 UTF-16 units that never split a surrogate pair or a combining sequence, posted to the owning process; a newline is a real Return key event between chunks. With the Korean source active, the Text Services Manager interprets key events by key code and composition state, so Unicode events are not trusted: the engine takes the paste route for the text and sends Return as key events. An app that ignores Unicode strings under a Latin source (the matrix in "Verification system" finds which) falls back to the paste route for that app, reported in meta. The vendor keys through the layout and drops what it cannot key; `src/mcp/surface.mjs`'s "paste emoji" rule is revised in M4 once the matrix shows what cua carries.

**Paste** (`paste {text, format: text|md|html}`): declare the pasteboard contents through a lazy data provider (an `NSPasteboardItem` whose data is supplied when an app asks for it: plain text; HTML as `public.html` plus plain; Markdown converted to HTML plus plain), post ⌘V to the owning process, and treat the provider's callback as the evidence that the app read the pasteboard (the vendor's mechanism, `R/E-helper-catalogue.md` §3; bounded at 2 s, then `Timed out waiting for the application to read the clipboard`); then restore the previous pasteboard contents only if the change count is still the engine's own (a human's newer clipboard is never overwritten; the vendor's "The user may have conflicted with your paste operation" sentence covers that case). Secret substitution is unaffected: the wrapper places the value into the request before the service runs, whichever route delivers it.

**Scroll**: scroll-wheel events in lines, `pages` × the scroll area's visible lines, at the element's centre or the point. **Drag**: down, interpolated moves, up, posted to the owning process.

**Settle.** After an action, before the next observation on that app, the engine waits for evidence of change and then for quiet. For the action's duration and after it, an `AXObserver` on the application listens for `kAXValueChangedNotification`, `kAXFocusedUIElementChangedNotification`, `kAXWindowCreatedNotification`, `kAXSheetCreatedNotification`, `kAXDrawerCreatedNotification`, `kAXMenuOpenedNotification`, `kAXMenuClosedNotification`, `kAXLayoutChangedNotification`, `kAXUIElementDestroyedNotification` and `kAXTitleChangedNotification`. If any arrives, the engine returns 150 ms after the last one, extended while a progress indicator or busy element is present in the window up to 5 s. If none arrives within 1 s of the action, the engine returns at 1 s: that is the vendor's floor, kept where nothing was observed, so a sheet that appears 300 ms after a click (TextEdit's keep-or-delete sheet) is caught by its creation notification rather than missed by a shallow signature. The cell's time budget is suspended around launch wait, action and settle through `nodeRepl.withSuspendedTimeout`, which the own host honours by pausing the budget on the worker's `suspend_timeout` (`src/repl-host/supervisor.mjs`).

**User intervention.** The contract is keyed on the driven app, not on the whole machine, because the purpose section promises that the user keeps working in another window. Two conditions stop a running action sequence and fail it with `userIntervened` and the vendor's "The user changed '<app>'…" sentence: the driven app became the frontmost application, or its key window changed, during the sequence (`NSWorkspace.didActivateApplicationNotification` and the key-window observation), which is how the user's click or keystroke reaches a background app; and, only while the driven app is already frontmost, physical input arriving during the sequence (the HID idle time from `CGEventSourceSecondsSinceLastEventType(.hidSystemState, .allEvents)` reset below the sequence's elapsed time; engine-posted events use the private source state and do not reset it). The pre-action guard, the vendor's "still interacting" refusal when the user touched input within the last second, applies only to coordinate input while the driven app is frontmost. After an intervention the engine refuses further actions on that app until a fresh `get_app_state` has been taken, as the vendor's state machine does (a debounce, then a forced re-query; `R/E-helper-catalogue.md` §6) and as its sentence tells the model. No event tap and no Input Monitoring permission are needed. Input through Screen Sharing counts as the user's (it enters at the HID level and activates windows like a local user); the spike confirms both halves on the mini with a keystroke the owner sends over Screen Sharing during an action.

**Lock screen.** `CGSessionCopyCurrentDictionary`'s `CGSSessionScreenIsLocked` true → every request fails `screenLocked` (−10020) with the vendor's first sentence. No auto-unlock, no guardian.

### The service: `src/services/engine/`

The service replaces `@oai/sky`'s macOS target behind `src/services/sky.mjs`. Its parts:

- **Client** (`client.mjs`): connects through `nodeRepl.nativePipe.createConnection(path)` (the own host's relay, `src/repl-host/native-pipe.mjs`, opens the socket outside the sandbox; the vendor host's relay does the same, which is what makes comparison A below possible), pings with `cua-engine-1`, launches the bundle through `launchServices.openApplication` when the connect fails, reconnects for up to 5 s, fails with the `cua install` diagnostic on a version mismatch, chains one request at a time with the 120 s default deadline, wraps launch wait, action and settle in `nodeRepl.withSuspendedTimeout`, and raises `SkyComputerUseError` / `SkyComputerUseTransportError` with the vendor's `errorName` values so `src/services/sky.mjs` classifies them unchanged.
- **Renderer** (`render.mjs`): `Skyshot` JSON → the vendor's text grammar (`R/A-contract.md` §3.2, the literal set in `R/E-helper-catalogue.md` §5, the composition rules `R/sky-behaviour.md` establishes): the `Window: "<title>", App: <name>.` header (whether an `App=` line precedes it is settled by M0's first real capture, since only the legacy MCP server's formatting shows one), one line per element, tabs per depth, index, localized role description, the flag words `selected`, `disabled`, `expanded`, `settable`, `selectable`, title, then the labels the vendor uses, `Description`, `Value`, `Help`, `URL`, `Details`, `Placeholder`, `ID`, `Rows`, `Columns` and `Secondary Actions`; long arrays rendered as `(showing N of M items)`; links rendered as Markdown with long URLs shortened; the focused-element and selected-text trailer; the truncation markers. The nine tree transformations and four Mac-only ones the vendor applies before rendering are named in E and decided in `sky-behaviour.md` from F and the captures.
- **Diff** (`diff.mjs`): per (connection, app), the default mode diffs against the previous rendered tree with the vendor's four headers and `~`/`+`/`-` marks or the `Removed element IDs:` summary, the no-change sentence when nothing changed, the full tree instead of the diff when the diff would exceed a line budget (the vendor's fallback; the budget from F or, failing that, measured against the captures), and `disableDiff` returns the full text; a screenshot-only observation advances the baseline as it does today (the first-call document says so).
- **Policy and approvals** (`policy.mjs`): before every app-scoped method, resolve the app (`resolve_app`), refuse the forbidden list (password managers and system security UI, the vendor's list from `R/E-helper-catalogue.md` §6, also enforced in the engine) with the vendor's sentence, classify risk (terminals and browsers high, with the subtitle), then ask once per (connection, bundle id) through `nodeRepl.createElicitation` with the exact message and meta shape the harness matcher expects (`scripts/accept/lib.mjs`; `R/A-contract.md` §2.6), remember the answer in the worker's memory, and fail `Computer Use was not approved to use <app>` on anything but accept. The memory is a `Map` in the module: the trusted worker lives exactly as long as the connection, so "once per connection" is the module's lifetime, with no session file (the vendor wrote `$CODEX_HOME/computer-use/sessions/<id>.toml`, which cua deleted at close; `scripts/accept/textedit.mjs` checked that file and changes in M3 to observe the behaviour instead: a second bind in the same connection asks nothing, a new connection asks again). `persist: ["session"]` only; `CUA_SHIM_PERSIST=always` is not implemented, by the owner's ruling that the plugin's Elicitation hook (`hooks/cua-approve.sh`) is where friction is removed and a stricter hook is where a veto lives. The policy lands in M1, before the first app-scoped method, so no release ever carries a selectable engine without it. **Linux** goes through the same module from M3: the window-bound methods (`get_window_state`, `click`, `press_key`, `type_text`, `scroll`, `drag`, `drag_handle`, `move`, `move_relative`, `perform_secondary_action`, `activate_window`, `key_down`, `key_up`) keyed by the window's `app` name, and `launch_app` by its app id; `list_apps`, `list_windows`, `get_screenshot` (the whole desktop) and the clipboard methods are not app-scoped and ask nothing, which `src/mcp/surface.mjs`'s Linux rule states from M3 instead of today's "no app asks for approval".
- **Result meta**: `codex/toolSurface` per call as today, plus `cua/nativeEngine {engine, version, build}` on every result and `cua/inputRoute` on every input result; the MCP proxy surfaces `cua/nativeEngine` in each `js` result's `_meta` next to `cua/replHost`, which is the attestation the harnesses validate.

### Engine selection, host switch and retirement

`CUA_NATIVE_ENGINE=vendor|cua` is resolved per connection in `src/runtime/launch.mjs` beside `replHostFor` (and mirrored in `scripts/repl-parity/selection.mjs`, as the host selection is): the env, else `~/.config/cua/engine.json`'s `engine`, else the default, which is `vendor` until M5 flips it to `cua`. The engine and the REPL host combine as follows on macOS with the computer surface; Linux is unaffected (its engine is `sky_linux` until #171):

| vendor | unset or vendor | any | vendor host through cua's compatibility executable, vendor service (today's path, reason `macos_native_peer_requires_vendor`) |
| vendor | cua | any | refused, `repl_host_refused`, today's sentence |

With `cua`, the launcher sets `CUA_SKY_SERVICE` to cua's service module and `CUA_ENGINE_APP` to the installed bundle, and `doctor` reports the selection, the bundle, its signature and the engine's permission state. M6 removes the vendor side on macOS: the runtime archive download; the manifest layout keys `node`, `nodeRepl`, `moduleDir`, `cuaRepl`, `skyServiceApp`, `skyVendorService`, `ipcClient` and `vendorManifest`; the compatibility executable and `CUA_REPL_HOST=vendor` on macOS; the vendor lanes of the harnesses take an explicit `--vendor-runtime <dir>` instead of the installed runtime. The archive's module tree is also where cells resolve their package imports (`CUA_REPL_NODE_MODULE_DIRS`: playwright, sharp, pngjs, jpeg-js, pixelmatch) and where `cua` loads `classic-level` for the Chrome profile directory map, so M6 supplies cua's own: `runtime/modules/package.json` with a lockfile pinning those packages at the versions the vendor tree carries, installed by `cua install` with `npm ci --omit=dev` into `$CUA_HOME/modules/<lock hash>/`, and `classic-level` moved into cua's own dependencies. That is the composite's macOS end state; #171 does the same for Linux.

### Install, signing and permissions

`cua install` builds the engine when the engine is selected (`CUA_NATIVE_ENGINE=cua`, or the default once M5 flips it) or when asked with `--engine`; otherwise it leaves the engine alone and `doctor` shows an `engine` row saying so, which keeps today's gates (`scripts/sandbox-probe/hosted-gate.sh`, `scripts/native-baseline/prepare.mjs`) running unchanged until they opt in. Building means `swift build -c release --scratch-path $CUA_HOME/engine/build` in `native/engine/`, assembling `cua Engine.app` under `$CUA_HOME/engine/<engineVersion>/`, and signing it with the identity named by `CUA_SIGNING_IDENTITY` or `~/.config/cua/engine.json`'s `signingIdentity` (a common name or SHA-1 from `security find-identity -v -p codesigning`), hardened runtime, no entitlements; a bundle whose `build` already matches is left as it is (reinstall changes nothing), and a replaced bundle's old engine is sent `shutdown`. The identity is the owner's Apple Development certificate (ruling 2026-10-18): its designated requirement names the certificate's subject, so a rebuild signed by the same certificate keeps the TCC grants, and the subject is the same string on every Mac the owner's Apple ID issues a certificate to, so each Mac may hold its own certificate. Without a configured identity a build refuses with the sentence that names the setting; `--engine-sign adhoc` exists for the hosted CI runner, where no permission is granted anyway, and is never a default: ad-hoc signatures change with every build and would lose the grants on each rebuild. The repository carries no certificate name. Signing over SSH (every harness install on the mini runs over SSH) needs the key's keychain partition list to admit `codesign` and the keychain to be unlocked; that is a one-time owner step on the mini, recorded in `docs/onboarding-new-mac.md` by M4 with the exact `security set-key-partition-list` command the owner runs with their password.

Permissions are requested where they are first needed and reported, never clicked: the first observation calls `AXIsProcessTrustedWithOptions` with the prompt option and fails `permissionsPending` (−10014) with a sentence naming "cua Engine" in System Settings → Privacy & Security → Accessibility; the first screenshot calls `CGRequestScreenCaptureAccess` the same way. Because macOS applies a Screen Recording grant only to a relaunched process, the engine exits after it observes the grant change (polling `CGPreflightScreenCaptureAccess` at the next screenshot request) and the service relaunches it. On the mini the owner grants both at the GUI console over Screen Sharing, once per signing identity. `cua doctor` reports both grants from the engine's `status` request, the signing identity, and whether the socket's owner is the installed bundle.

### Verification system

The owner's core requirement: no regression across the replacement, proven, before any default changes. The system has seven parts, built in the milestones that first need them and run in full at M5.

1. **Three comparisons on the native baseline harness.** The vendor engine accepts only the vendor host, so "same host, different engine" is possible only on the vendor host, where cua's service runs inside the vendor trusted worker (loaded through `CUA_SKY_VENDOR_SERVICE`, the slot `src/services/sky.mjs` already delegates to; the vendor relay connects to any absolute socket path). `scripts/native-baseline.mjs run` takes `--host` and `--engine` independently (`--host vendor --engine cua` is the loaded-service lane) and records the engine attestation from `_meta['cua/nativeEngine']`, with the helper attestation classifying both `SkyComputerUseService` and `cua-engine` processes. Three `compare` modes, each judging every row the default compare judges (per operation, the candidate's median within baseline + max(10%, 500 ms), p95 and max reported, three attested runs per side with every planned sample present, else NO VERDICT) and each naming exactly which attested fields may differ:
   - **A, engine only**: `--host vendor --engine vendor` against `--host vendor --engine cua`; host, sandbox and service equal, engine differs. Attributes a loss or a win to the engine.
   - **B, host only**: `--host vendor --engine cua` against `--host cua --engine cua`; engine equal, host and sandbox differ. Prices the own host's relay (every socket chunk crosses the supervisor as base64 JSONL) and sandbox.
   - **C, end to end**: `--host vendor --engine vendor` against `--host cua --engine cua`; the product verdict, labelled as two variables.
   A fresh vendor triple is taken in the same sitting as each candidate triple; the 2026-10-14 runs remain a reference, not a side. Every macOS computer run passes `--approved-runtime`, as the harness requires.
2. **Scenes.** Four harness-owned windows, one per app family, each with run-owned content and the TextEdit fixture's refusal discipline (the harness refuses to start when the app has windows that are not its own): TextEdit (AppKit text), Finder (AppKit lists, a run-owned folder with 200 files), Chrome (the mini's branded Chrome, in the harness's own registered profile window as the browser parity harness uses; its own UI and a loopback page the harness serves; never the owner's windows, never killed), and one Electron app present on the mini, chosen in M0 by inventory. Each scene's window is the driven app's only window. Scenes pair for the non-interference cells: the user window of a cell is the scene window of another family (TextEdit ↔ Finder, Chrome ↔ TextEdit, Electron ↔ Finder), so the driven app and the user's app are never the same process. Breadth is the ruling, scenes are the proof: the engine must handle any ordinary app; the harness proves it on these. The scenes' fixed-state definitions and refusal checks are written in M0 for the spike and promoted into the harness in M1.
3. **Differential suite and goldens.** `scripts/repl-parity.mjs run --suite native-mac --host … --engine …`, the same scripted cells on both engines, then `diff <vendor> <cua> --expected <declared>`: the accessibility text on the scenes' own windows is compared **modulo index renumbering** (indexes replaced by order of appearance; the vendor's lines, normalized to role, flags, title and labels, must appear in cua's text in the same order; lines cua adds are allowed only when the declared file names each added element by role and title and no golden declares more than 10% added lines without a Decision Log entry) and structurally where a window could carry the user's content. The same rule pins the renderer's goldens under `test/native-goldens/`: both engines' outputs recorded on the same scene states in one sitting (M1), so drifting state cannot separate them. Expected differences are declared, as `vendor-defects.mjs` declares them today, never silently absorbed.
4. **Method matrix.** The 11 methods × the four scenes plus TextEdit's Open panel (an out-of-process target), outcome equal sample for sample or strictly better (the Linux `method.*` rule), including the error sentences for refused cases (select on a non-text element, set on a non-settable one, an invalid index, an app with no window) and the `cua/inputRoute` that carried each action. `scripts/native-matrix.mjs` runs it on a device for one engine and `compare`s two runs; it also writes the per-scene speed cells and the three-point summary below.
5. **The three points, defined.** *Speed*: on every scene, in-cell medians of `getAXState`, `getScreenshot`, `listApps` and each method cell, from the matrix runs, lower than the vendor's by at least 10% with p95 not worse, three runs per side; the no-regression gate of part 1 stays the inherited rule, this is the stricter "beat". *Finding elements*: per scene a fixed list of ten targets chosen in M0 where the spike's recordings show the vendor's text missing or unnamed elements (web content and Electron are where that is expected), each to be resolved by name through the model's path (`getAXState` text search → index → action), plus the share of element lines with a non-empty title or label and the `ID:` count; the vendor's scores are recorded first, cua's are not lower on any measure, and the sum of resolved targets is higher, or every measure is equal, in which case the report records parity and the owner decides. *Not interfering*: for each paired scene cell the harness activates the user window, drives the scene's app, and after every action reads, from the device side and independently of either engine, the frontmost application (`lsappinfo front`, the existing `FRONTMOST_SCRIPT` in `scripts/accept/key-guard.mjs`) and the topmost on-screen window's owner pid and bounds (`CGWindowListCopyWindowInfo`, which needs no permission when names are not read) and requires both unchanged and `cua/inputRoute ≠ 4`; the vendor's score is recorded on the same cells. The #162 key guard, which refuses keys unless the target is frontmost, gains one allowed case for these cells: the frontmost window is the harness's own user window of this run, identified by owner pid and bounds; it stays as strict as today for every other window. A further cell, **concurrent use**, has a physical-equivalent keystroke delivered to the user window during a driven action (in the spike, the owner over Screen Sharing; in the suite, a device-side probe that posts at the HID event tap from outside the engine under test) and requires the action to complete and the keystroke to land in the user window.
6. **Korean and Unicode matrix.** `typeText` and `paste` of: `The quick brown fox jumps over the lazy dog.`, `한글 테스트`, `ㄱㄴㄷ`, `가나다 abc 123`, `😀 이모지`, `é` as e plus U+0301, `日本語`, and `줄1⏎줄2` (⏎ a Return key event), into the TextEdit scene, the Chrome loopback page's textarea and the Electron scene's text field, run twice: with the Latin input source active and with the Korean source active, and once more with a Hangul composition in progress in the user window; read back by SHA-256 inside the cell and compared with the expected string. A mismatch is a failed row; a failed row with a named cause (autocorrection, an app that ignores Unicode events) is declared in the expected file with that cause, never silently absorbed.
7. **Unit goldens and tests.** The renderer and diff against recorded `Skyshot` trees and the vendor's recorded text (part 3's rule); a settle cell, "the observation right after an action equals the observation two seconds later", scored on both engines in the differential suite; protocol framing and the 8 MiB bound; the policy module (forbidden list, risk, once-per-connection memory, the elicitation shape against the harness matcher); the selection table above (`test/runtime-launch.test.mjs`, `scripts/repl-parity/selection.mjs` cases); secret substitution shapes unchanged (`test/services-sky*.test.mjs`); the untrusted-engine error path (the hosted runner has no grants, so `permissionsPending` is testable there).

Gates: the hosted macOS runner (`.github/ci-kit.yml`) builds the engine ad-hoc, runs 7 and the engine's untrusted paths on every PR; the live parts (1–6) run on the mini inside a CI-opt hold, GUI, with the owner's one-time grants. The default flips to `cua` (M5) only when 1–6 pass with three attested runs on each side.

## Interfaces and Dependencies

**EngineProtocol** (`native/engine/Sources/Engine/Protocol.swift`, `src/services/engine/protocol.mjs`): JSON-RPC 2.0 over the 4-byte little-endian length-prefixed framing, 8 MiB per frame; methods `ping`, `execute`, `status`, `shutdown`; `serverApiVersion = "cua-engine-1"`.

```
ping     {clientApiVersion: string} → {serverApiVersion: string, engineVersion: string, build: string}
execute  {method: string, args: object, deadlineUnixMilliseconds: number, lineage?: string} → result | error
status   {} → {engineVersion, build, accessibility: boolean, screenRecording: boolean, socket: string, pid: number, bundlePath: string}
shutdown {} → {} then exit, or error "busy" while another connection is open

methods: list_apps, get_app_state, click, drag, paste, perform_secondary_action, press_key, scroll, select_text,
         set_value, type_text (the facade's shapes, R/A-contract.md §1.4), resolve_app {app}

resolve_app → {appPath: string, bundleIdentifier: string, displayName: string, isRunning: boolean, pid: number | null}
get_app_state {app, disableDiff?: boolean, includeScreenshot?: boolean, outputDirectory: string} → Skyshot
Skyshot  {app: {bundleIdentifier, displayName, appPath, pid}, window: {title: string, frame: Rect, pid: number},
          lineage: string, revision: number, nodes: Node[], truncated: {depth?: number, count?: number} | null,
          screenshot: {url: string, width: number, height: number} | null, focused: number | null,
          selectedText: string | null}
Node     {index: number, depth: number, pid: number, role: string, subrole: string | null, roleDescription: string,

          actions: string[], frame: Rect | null, children: number}
input results → {meta: {inputRoute: 1 | 2 | 3 | 4}}
error    {code: number (the vendor's codes where mapped; -10005 otherwise), message: string}
```

**EngineClient** (`src/services/engine/client.mjs`): `connect()`, `execute(method, args, {deadlineMs = 120_000, lineage})`, `status()`; owns the one-in-flight chain, the launch-on-failure path through `nodeRepl.launchServices.openApplication` and `nodeRepl.nativePipe`, the `withSuspendedTimeout` wrapping, and the error classes.

**SkyshotRenderer** (`src/services/engine/render.mjs`): `render(skyshot) → string` in the vendor grammar; **TreeDiff** (`src/services/engine/diff.mjs`): `diff(previous, current) → string` with the vendor's headers; both pure, golden-tested under part 3's modulo-renumbering rule.
