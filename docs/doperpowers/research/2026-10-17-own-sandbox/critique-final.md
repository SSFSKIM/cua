#115 sandbox design critique: converged after two rounds. The main session adopted all ten findings and all nits; three refinements it proposed were accepted with small additions; one fork goes to the owner. Final list, each with its reason.

1. Create each deny target (0700, idempotent) before rendering the policy; refuse the launch if creation fails; emit paths through cua's realish() (sandbox.mjs:62). Reason: Linux bwrap.rs append_unreadable_root_args (line 1342) emits no mask for a missing path while `--ro-bind / /` is a live view, so a store or config dir created mid-session is readable by the running kernel; macOS normalize_path_for_sandbox (seatbelt.rs:217) falls back to the logical path on a missing target, which a symlinked ancestor defeats.

2. One deny resolution in buildLaunch (CUA_SECRETS_DIR and its project tier, else the default store path when secrets are off; $HOME/.config/cua; the home's state/), passed to both hosts as CUA_SANDBOX_DENY_READ (JSON array of absolute paths); missing or malformed on a non-disabled launch refuses; the list joins the scoped preflight's protectedPaths; the kernel role applies it and the worker role ignores it; the children's launch key stays the policy-state key (mode plus cwd), not the role-rendered profile. Reasons: the kernel must be denied exactly what the worker reads; a write root nested inside a deny entry would re-open that subtree under the original's most-specific rule, so refuse it at launch; supervisor.mjs runJs stops the worker whenever `worker.key !== launch.key`, so role-specific keys would restart the worker on every call.

3. Seatbelt port scope item: nested lesser-access entries become read-only subpaths of the enclosing write root (permissions.rs:1696-1745); a golden fixture for an explicit read entry nested in a write root; a vendor-host acceptance item "a cell cannot write into node_repl's script directory"; role detection by script basename, not path. Reason: shim.log shows node_repl writes kernel.js and trusted-worker.js into a random .tmpXXXXXX under TMPDIR (the scoped write root) and passes it as a read entry; that exclusion is the only thing between a cell and overwriting trusted-worker.js before the worker's lazy first start.

5. Fingerprint wording bounds the difference to the probed operations. Byte-level oracle for cua's two inputs: a C poller that spawns the CLI itself and busy-loops proc_listchildpids + KERN_PROCARGS2 to catch sandbox-exec's argv in its profile-compile window (bounded retries); eslogger optional because root plus Full Disk Access is the owner's grant. If neither works, the chain is recorded as having a behavioural link there.

6. Hard-link and clonefile probes on macOS, link probes on Linux, pinning that the base profile never allows file-link or file-clone. Reason (verified on this Mac with toy sandbox-exec profiles): under `(allow default)` a hard link reads a file whose path is denied by `(deny file-read* (subpath ...))`; under the original's deny-default shape both `ln` and `cp -c` fail EPERM. The deny holds only through that invariant.

Reason: has_full_disk_read_access() is false with any Deny entry (permissions.rs:921-926), which drops seatbelt_preferences_policy.sbpl with no platform-defaults file to replace it; this profile is tighter than anything cua has run.

Whichever way, the `sandboxed` advertisement and tool text name which child is confined.
