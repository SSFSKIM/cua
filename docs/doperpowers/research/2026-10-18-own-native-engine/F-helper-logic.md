## 2. Naming and pruning

All predicates are in `UIElementTreeTransformation.transform(item:context:rebuild:providerTitle:render:)` 0x1006473d0 (`1006473d0_…transform.c`) unless named; the render closure passed to every transformation is `TransformedUIElement.lmReadableDescription(for:)` 0x10074b118 (`FUN_100749d50`).

1. **Pipeline and order.** `defaultPipeline` (static 0x1013f94c8) = cases 0…8 in declaration order; the Mac pipeline (`FUN_10074a3b4`) = `filterActions`, the nine, then `removeElementsUnderCalendarEvents`, `retrieveAttributedTextFromTextAreas`, `retrieveAttributedTextFromWebAreas` (**[inference]** concatenation order from call order). Each item runs the whole pipeline, then its resulting subtree is transformed (`FUN_100640ca0` → `FUN_100640ed4`; **[inference]** preorder). Helper predicates: `hasDescriptiveAttributes` (0x10074b190) = description, value, title or placeholderValue non-empty, or role `AXImage`; `Item.hasDescriptiveAttributes` (0x10063eed8) = the same over the node **and its descendants**; `isFocusableOrSelectable`; `canBeUserInteractive` (0x10074fbfc): `AXStaticText` → focusable ∨ selectable, `AXTextArea`/`AXGroup` → focusable, else true; `hasInterestingActions` (0x10074f994) = any action other than `AXScrollToVisible`, `AXShowMenu`.
2. **The nine.** (0) `associateTitleUIElements`: a child that serves as title (`AXServesAsTitleForUIElements`) for exactly one element gives its text (value, else title, else description) to that sibling's `title` and is removed (multi-target branch not traced). (1) `flattenIntoSelectableAncestor`: node selectable, not focused, role ≠ `AXTable`, subrole ≠ `AXTableRow`, no descendant settable or selectable → `title`/`description`/`value` := the flattened titles/descriptions/string values of the subtree, `isFocusable` := any descendant focusable, children := only descendants whose `AXValue` is a Bool (toggles). (2) `pruneNonDescriptiveSubtrees`: **removed** unless the node is focusable or selectable, has an interesting action, has descriptive attributes in its subtree, or a descendant is focusable/selectable or has an interesting action; Mac pre-check (`FUN_1007486f4`) outside `fullUIContext`: a childless node with no descriptive attributes that is not focused, selected or disclosing is removed. (3) `pruneEmptyDisabledElements`: removed when disabled, not focused, childless and without descriptive attributes. (4) `mergeSingleItemGroups`: `AXGroup`, not selectable, not focused, no descriptive attributes: one child without a partial-array marker → **replaced** by it; no children → removed. (5) `flattenRedundantHierarchy`: node not selectable, not focused, no descriptive attributes: a child with the same role, no partial-array marker and **the same rendered line** is replaced by its own children. (6) `flattenRepetitiveStaticText` (`FUN_10064bc48`): node not focusable, not selectable, no user-interactive descendant: a child whose trimmed description is contained in the node's description, or whose trimmed value is contained in the node's string value, is dissolved into its children, recursively. (7) `flattenLinksIntoMarkdownText`: `AXLink` with a URL → the subtree text becomes a Markdown link (`TransformedUIString.appendInterpolation(_:role:context:)` 0x1006284ec), role `AXStaticText`, roleDescription `link`, url nil, children removed. (8) `mergeTextOnlySiblings`: node not selectable, not focusable: consecutive text-only children (static text with a string value, or a leaf link rendered as Markdown; `FUN_10064c228`) are merged into the run's first element (join rule in `FUN_100646f38`, not read); `flattenedRole` (`FUN_10074fd94`): `AXRadioButton` → `radio button`/`radio buttons`, `AXRow` → `outline row`/`rows`.
3. **The four Mac-only** (`FUN_1007486f4`): `filterActions` (fullUIContext only) rewrites `actionDescriptions` through redacted 0x100782c24 with `isCatalyst` (predicate not traced; the `__data` action order of E §2.1 is its likely allowlist **[inference]**); `removeElementsUnderCalendarEvents`: `AXStaticText` with roleDescription `Event`, one static-text child, app `com.apple.iCal` → children cleared; `retrieveAttributedTextFromTextAreas`: `AXTextArea` whose `AXTextualContext` ≠ `AXTextualContextSourceCode` → `AXAttributedStringForRange` over the value's length (or its truncation range) → Markdown (`FUN_10075ef40`) into `value`; `retrieveAttributedTextFromWebAreas`: **only in `informationalContext`** (never for `get_app_state`), `AXWebArea`, not Chromium → text markers → Markdown.
4. **The element line** = `indent × depth` + `"<id> "` + text (+ `" " + detailText`), `text` = non-empty pieces of **[roleWord, flags, details] joined by one space** (`accessibilityDescription` 0x100615504 → `FUN_10061552c`):
   - **roleWord** (`FUN_1006156c8`): the localized `AXRoleDescription`, except kind `row` → `row`, kind `generic` with empty description → `element`, kind other with role `AXGroup` → `container`, and **nothing** for `menuBarItem`, `menuItem`, `radioGroup`; without a role description: `menu`, `menu bar`, else `unknown`. Kinds from `UIElementRole.presentationKind` 0x10074b324.
   - **flags** (`FUN_10061683c`): `(` + join `", "` + `)` of, in order, `selectable` (selectable and not selected; fullUIContext only), `selected`, `disabled` (not enabled; not for `AXGroup`/`AXStaticText`, not in informational context), `expanded` / `collapsed` (disclosable), `settable` or `settable, <valueTypeName>` (plain when the type is `string`), `sent by me` (`domClassList` contains `is-sender`).
   - **details** (`FUN_100615aac`), parts in order: title (bare), `Description`, `Rows: a-b`, `Columns: a-b` (only when lower < upper), `URL` (shortened), `Help`, `Value`, `Details` (= `AXValueDescription`), `Placeholder`, `ID` (the `AXIdentifier`, **dropped entirely when it starts with `_` or `NS`**, not stripped; this corrects E §5.2), `Secondary Actions` (presentation actions minus kinds press/showMenu/scrollToVisible and the descriptions `Add comment`, `Remove unused rows`, `Remove unused columns`, `Remove unused rows and columns`; joined `", "`). A part whose value equals an earlier part's value is skipped (`FUN_1006170dc`). Long parts (`isLong`: about ≥ 100 characters or containing `\n`, `FUN_1006185bc`) move after the short ones, stably. **If exactly one part remains and it is not `Secondary Actions`, only its value prints**; otherwise `Label: value` (title bare) joined `", "`. Details are skipped only in informational context for menus and for buttons/checkboxes/menu buttons without descriptive attributes.
   - **detailText** = `Item.availableSubsetDescription` 0x10063e220: `(showing <lo-hi>, <lo-hi> of <count> items)` from `availableRanges` (**[inference]** `Range` bounds), only when ranges exist.
5. **URLs** (`UIElementURLShortener`; defaults `individualLimit nil, totalLimit nil, includeQuery true, includeFragment true`, `flatTree` disasm 0x100709d14): per URL (`FUN_10064f45c`) schemes `webdoc`, `data` and one unread literal, and image URLs, are not rendered; `http`/`https` scheme, leading `//` and host `www.` are removed; over `individualLimit` → first `limit − 1` characters + `…`. `compactConfigurationIfNeeded` 0x10064f274: `totalLimit` defaults to **4,000 characters per tree**; while over it: drop fragments, then queries, then `individualLimit` = 120, 110, … 20 (`FUN_10064fa64(120, 20, 10)`); `shortenURLsIfNeeded` 0x1007478ac renders then compacts. Links print `[text](url)` (`appendMarkdownLink` 0x100629d20).
6. **Header, trailer, `App=`.** `AccessibilityTreePresentation.init` 0x10062691c: `Window: "<title>", App: <appName>.\n` + lines joined `\n` + `\n`; then (`FUN_100626be4`) selected text → a blank line, `Selected text: ` and the text fenced in three backticks on their own lines, then the note (E §5.1); else selected elements → `\nSelected:\n<lines>` + note; else focused element → `\nThe focused UI element is <line>`; **the focused line is omitted when there is a selection**. `llmDescription` 0x10022ac8c defaults title and app name to `Unknown` and appends `\n\nNote: In order to be usable, Spotify app links…` for `com.spotify.client`. **No `App=` line is produced by either function; the literal exists only in the `ComputerUseClient` (legacy MCP) module.** cua's TextEdit test double's first line (A §3.2) is therefore not what the IPC text carries **[inference from the two producers; a recorded capture confirms]**. The Google Docs regex is not a text rule (§4.8).

**What cua reproduces.** The 9 + 4 transformations with the predicates above in pipeline order; the line `<id> <roleWord> (<flags>) <parts>` with the role overrides, flag order, part order, value dedupe, long-last and single-part rules, the `ID` drop rule, the 4,000-character URL budget; the header without `App=` and the trailer precedence (selected text > selected elements > focused element).

## 3. Index assignment and re-resolution

Structures: `UIElementTreeRevision {lineageID, tree, renderTree, focusTree?, focusRenderTree?, ids: UIElementTreeTable<AXUIElement, Int>, changes, previousRevision?}` (a class; S.fields:4086), `UIElementRender<ID> {id, elementID: Int?, text, detailText?, sourcePath: IndexPath?, children}`, `ID == AXUIElement` for `TransformedUIElement`. The chain is kept whole (`lineageRootRevision` 0x100639018 walks `previousRevision` back to the root).

1. **Numbering a fresh tree.** `UIElementTreeRevision.root(_:focusTree:lineageID:render:)` 0x100645c74 renders the transformed tree, then `setElementIDs()` 0x10062d3d4 (`10062d3d4_…setElementIDs.c`) runs `depthFirstTraversal().enumerated()` and sets `elementID = offset`: **0-based, contiguous, DFS preorder over every rendered node** (the iterator pops and pushes children reversed, `10063b748_…UIElementDepthFirstIterator_next.c`), the order the text prints. Nodes the transformations removed never get an ID; `detailText` is `Item.availableSubsetDescription` (the `(showing N of M items)` text). The lineage id is `UUID(timestamp: Date.now).uuidString.lowercased()` (0x10075a248).
2. **Keeping an ID across revisions.** `appending(tree:focusTree:render:)` 0x10064551c (`10064551c_…appending.c`) renders the new tree, runs `UIElementRenderDifference(oldTree: self.renderTree, newTree:)`, calls `inheritElementID()` 0x10062eb64 on every change (copies `old.elementID` into the new node for the `none` and `update` cases only), then the revision initialiser `FUN_10064435c` which keeps an existing `elementID`, else reuses the ID already given to the same `AXUIElement` in this revision, else takes `NextAvailableElementIDIterator.next()`. The matching (`FUN_10062f10c`, driven by `Iterator.next` 0x10062c474) is **structural, sibling list against sibling list under matched parents, against the immediately previous revision only**: walk the common prefix while `old[i].id == new[i].id` (Swift `==` on `AXUIElement`, i.e. `CFEqual`); for the remainder, a dictionary of the remaining old nodes by id; a new node absent from it is `insert`; one present is `none`/`update` only if it is in a "stable" set (`FUN_100627090`/`FUN_10063880c`, **[inference]** a longest-increasing-subsequence over old offsets), otherwise `insert` with the old entry dropped silently; leftovers are `remove`; matched pairs queue their children (`FUN_100630190`). `update` iff `text` differs; `detailText` is never compared. So an element keeps its ID while its handle stays `CFEqual` under a matched parent; it loses it when it moves to another parent, is reordered out of the stable set, has an ancestor replaced, or is missing from even one revision.
3. **Retirement and reuse.** `ids` holds only the current revision's nodes; `item(for:)` 0x100644f64 resolves an ID on that revision only, so a retired ID is `<n> is an invalid element ID`. But `next()` 0x10062e368 (`FUN_10062e3bc`) returns `max(surviving non-nil elementIDs) + 1, +2, …` (nil counted as 0; in an all-new tree the first new ID is 1): **IDs above the surviving maximum are reused** (IDs 0…20, node 20 removed, one node added: the new node is 20). Nothing on the action path reads `lineageID` (`FUN_1002207b8` → `item(for:)`), so a stale reused ID resolves silently to the new element. A focus-only node (`focusTree`) is never diffed and **[inference]** takes a fresh `max+1` every revision.
4. **New lineage.** `FUN_10022cb30` (branch at 0x10022dbe0) starts a `root` when `!enableAXDiffing || continuingFrom == nil`, else `appending` onto `continuingFrom`. `updateSkyshot` sets `enableAXDiffing = controller.isAXTreeDiffingEnabled && !disableAXDiffing` and `continuingFrom = lastAXTree?.systemSelection.windowRevision` (`10006cadc_FUN_10006cadc.c`). Hence: `disableDiff: true` → **new lineage, IDs renumbered from 0, full tree**; diffing off on the controller → every observation a new lineage; a new controller (no `lastAXTree`) → new lineage. No window-identity check exists on the path: **[inference]** a key-window switch appends to the old window's lineage and the diff then overflows the budget (§4) into a full tree. `updateSkyshot` throws when `runningApplication.isTerminated` (`10006c064_FUN_10006c064.c`); **[inference]** the replacement controller starts a new lineage.
5. **Resolving an action's ID.** `prepareToInteract` (disasm 0x10006fe1c) and 0x10007022c call `lastAXTree.refetchElementIfNeeded(id, validateElement: true)` 0x1002207b8: `item(for:)` nil → `invalidElementID(id)`; else `refetchElementIfNeeded(element, validateElement:, ignoreValueChange: false)` 0x100220a14 (`100220a14_…refetchElementIfNeeded.c`): no `invalidationMonitor` → `noInvalidationMonitorProvided`; read the monitor's `State {layoutChanged, destroyedElements}`; if `!layoutChanged` and the element is not in `destroyedElements`, **no re-fetch**: with `validateElement` read `AXRole`, and only `kAXErrorInvalidUIElement` (−25202) → `elementNoLongerValid`; anything else passes with the cached element. The monitor (`UIElementTreeInvalidationMonitor.init(app:)` 0x100759878) registers `layoutChanged` and `uiElementDestroyed` on the application element.
6. **Re-fetch (`FUN_100220f24`).** Re-read the element live (`TransformedUIElement.init(element:)`); if it still matches the cached copy, return it. Else count the cached element's matches in the **current** tree (`FUN_100222294` over `windowRevision.tree`); count ≠ 1 → `elementAmbiguousBeforeRefetch`. Then `refetchTree()` 0x1002226f0 re-runs extraction (same monitor, `continuingFrom: current windowRevision`, `enableAXDiffing: isAXTreeDiffingEnabled`) and **writes the new `SystemSelection` into `self`** (`FUN_1002245a8`); count matches in the new tree: 0 → `elementNoLongerValidAfterRefetch`, 1 → that element, >1 → `elementAmbiguousAfterRefetch`. Since `lastAXTree` is this object, **[inference]** the next observation diffs against the re-fetched revision, not the one the model saw. The match predicate `FUN_100221838` is a conjunction of exact equalities (nil equals nil) over `role` (CFEqual), `subrole`, `roleDescription`, `title`, `value` (skipped when `ignoreValueChange`), `valueDescription`, `description`, `placeholderValue`, `help`, `identifier`, `url`: **no path, position, frame or pid**. `ignoreValueChange: true` is used only by `RefetchableUIElement.refetchIfNeeded(validateElement: true, ignoreValueChange: true)` after `setValue(_:forAttribute:)`.
7. **Sentences** (`Error.description` 0x1002225b8): `invalidElementID(n)` → `<n> is an invalid element ID`; `elementAmbiguousBeforeRefetch` → S.strings:29192 (`…couldn't be started…`); `elementAmbiguousAfterRefetch` → 29191 (`…couldn't be finished…`); `elementNoLongerValid` and `elementNoLongerValidAfterRefetch` → 29190 (`The element ID is no longer valid. Try to get the on-screen content again and see if that resolves the issue.`); `noInvalidationMonitorProvided` → 29193.

**What cua reproduces.** Preorder 0-based numbering of rendered nodes; ID inheritance by `CFEqual` sibling-structural matching against the previous revision; the four sentences and their trigger order (invalid id → cached validation → before/after ambiguity). The two vendor defects, reuse of IDs above the surviving maximum and the lineage reset on `disableDiff`, are design decisions for `sky-behaviour.md`, not parity to copy blindly.

## 4. Diffing

1. **Who decides.** The controller always asks for `difference(.previous)`: `updateSkyshot`'s result partials call `SystemSelection.llmDescription(mode = 1, lineOptions = [])` (`10006decc_…`, `10006d5e8_…`; mode bytes 0 `.initial`, 1 `.previous`, 2 `fullTree`). `llmDescription` 0x10022ac8c (`10022ac8c_…llmDescription.c`) then: no `previousRevision` → full tree; `differenceLines` nil (budget) → full tree; empty lines → the no-change sentence; else the diff. **Mode 0 (`.initial`, the cumulative header S.strings:29202) is passed by no caller**; the five call sites pass 1, 1, 1, 2, 2. The full-tree getter adds `.withoutElementID` only for `contextType == .informationalContext`.
2. **Texts** (all through `AccessibilityTreePresentation.init(body:focusedElement:selectedText:selectedElements:)` 0x1006268d4, so the focused-element/selection trailer stays and the `Window: "…", App: ….` header does not). With `X` = `Window: "` + title (or `Unknown`) + `"`: diff = `The following is a diff from the previous accessibility tree for ` + X + ` ` + legend + `\n` + lines joined by `\n`; no change = `There has been no change in the accessibility tree for ` + X + `.` (e.g. `…for Window: "Untitled".`). The legend is chosen by `FeatureFlag.axTreeDiffingRemovedElementIDRanges.isEnabled` (= `summarizesRemovedElementIDs`), **not by list length**: true → 29201 (`…Removed elements are summarized by ID range.`), false → 29200.
3. **Budget** (`differenceLines` 0x100618ddc, disasm 0x1006191cc–0x10061a4f8): `fullTreeLineCount` = node count of the current main render tree; the remaining budget starts equal to it; each change's lines (`lineCounter`, `FUN_10061b088`) are subtracted; a change with more lines than remain → `onLineBudgetExceeded(.difference(fullTreeLineCount:))`, return nil → full tree. **The diff body may have at most as many lines as the full tree (ratio 1.0).** In summarise mode `remove` changes are set aside and not counted, but with removals and `remaining < 1` → `.removedElementSummary(fullTreeLineCount:)`, nil → full tree. `ignoreDifferenceLineBudget` is false on this path; the handler only logs.

## 11. The soft-link table

**The scheme** (`SoftLink` module). `SoftLink.sipHash(buffer:appending:)` 0x100238f48 (`100238f48_SoftLink_sipHash.c`) is textbook **SipHash-2-4** over `buffer ‖ appending`: its initial state words are 0x7469686173716475, 0x6b617f6d656e6665, 0x6b7f62616d677361, 0x7b6b696e727e6c7b, which XOR with the SipHash constants `somepseudorandomlygeneratedbytes` back to the key **k0 = 0x0706050403020100, k1 = 0x0f0e0d0c0b0a0908**, the reference test-vector key (bytes 00…0f); two compression rounds per block, `v2 ^= 0xff`, four finalisation rounds, length byte in the last word. `SoftLink.hash(_:appending:)` 0x100240eac is the same over a `String`'s UTF-8 followed by the buffer; `hashWithPrefix(_:prefix:)` 0x100241d3c is the same over `prefix ‖ string`.

**Salts.** 28 lowercase-hex strings of 125 to 128 characters live in `__TEXT.__const` (E §3.1 listed them; addresses 0x10110eca0, 0x101114920 … 0x1011155b0 for the 19 used by the SystemSoftware and ComputerUse modules, 0x101145a30 … 0x101145f60 for 9 used by SlimCore/Messages). Each soft-linking module passes its own salt string to `lookUpBatchSymbolPointers(images:symbolRequests:salt:)` 0x10023a380 (`10023a380_…lookUpBatchSymbolPointers.c`), whose callers are the modules' `_swift_once` initialisers: `FUN_100249218` (CGEventAPI, salt 3, 24 requests), `FUN_10025acdc` (WindowServerSPI + ApplicationRegistrySPI, salt 18, 13 requests), `FUN_100247820` (AccessibilitySPI keys, salt 1, 7 requests), `FUN_100247ed8` → (AccessibilitySPI functions, salt 2, 3 requests), `FUN_1002582d8` (an `NSUserActivity` private initialiser, salt 5, 2 × `objc_msgSend`), and `lookUpSymbolPointer` 0x10023a28c/0x10023a12c for the single SkyLight requests (salts 8 to 17) and the responsibility lookup (salt 0).

**Per-symbol scheme.** A `SymbolRequest` is a static `[UInt64]` of **two alternatives** (`symbolRequestsByHash` 0x10023a6c0 indexes every alternative; `FUN_10023e500`, the export-trie walker called from `lookUpExportedSymbol` 0x10023e328, forks the SipHash state at every trie node, appends the **salt after the name** at a terminal node, finalises and looks the 64-bit value up):

- alternative 1 = `SipHash24(k, "_Name" ‖ salt)`, the export-trie spelling with its leading underscore;
- alternative 2 = `SipHash24(k, "Name" ‖ salt)`, the `dlsym` spelling (the walker calls `_dlsym` for trie entries that are re-exports, which is how every CGEvent function is reached: in the shared cache CoreGraphics re-exports them from SkyLight's `SLEvent*`); verified on `CGEventPostToPid` (0x1013e6cf8 / 0x1013e6d00).

**Per-image scheme.** `lookUpImages(images:salt:)` 0x10023b6e4 walks `_dyld_image_count`/`_dyld_get_image_name` and compares `SipHash24(k, installPath ‖ salt) & 0x00FF_FFFF_FFFF_FFFF`; the stored word's top byte is the `ImageSearchStrategy` (0 framework, 1 privateFramework, 2 library, 3 path) that `loadImagesFromFilesystem` 0x10023bec0 / `resolveImagePaths(name:strategy:)` 0x1002423ac use to `dlopen` a candidate when the image is not loaded (templates `/System/Library/Frameworks/`, `/System/Library/PrivateFrameworks/`, `.framework/Versions/{A,B,C,Current}/`, `/usr/lib/…dylib`). Each image list carries the path in every `Versions/` spelling (e.g. five CoreGraphics words at 0x1013e6a08–0x1013e6a28, six HIServices words at 0x1013e61c0–0x1013e61f8), which is why E's `[inference]` about templates was right.

## 13. Where the design sections differ from the code

Each item quotes the spec's "Design" and gives the section above that holds the evidence. These are inputs to `sky-behaviour.md` and to the Decision Log, not verdicts: several of the spec's choices are deliberate departures (its own timeouts and lineage check), and the list marks those.

**Observation**
1. "its `AXFocusedWindow`, else `AXMainWindow`; none → error": the vendor has a third fallback, the last entry of `AXWindows` (§1.7).
2. "`AXUIElementCopyMultipleAttributeValues` fetching, per element in one call, role, subrole, role description, title, description, value, identifier, enabled, focused, selected, position, size and children, then `AXUIElementCopyActionNames`, and `AXUIElementGetPid` for every element": the vendor prefetches a 20-attribute set without position, size, actions or pid through `AXUIElementCopyHierarchy` (always on for `get_app_state`) and falls back to `CopyMultipleAttributeValues` only for elements the prefetch missed; `AXUIElementGetPid` is never called by the walk (§1.1–1.4, 1.8). The spec's per-element batched fetch is cua's public route by design; the attribute set to prefetch is the vendor's 20.
3. "The messaging timeout is set to 1 s on every element it touches … a whole observation has its own 10 s traversal deadline": the vendor has neither (§1.6). cua's additions, not parity.
4. "Chromium and Electron apps get `AXManualAccessibility` and `AXEnhancedUserInterface` set once per process": one or the other, never both; `AXManualAccessibility` for apps that list it, `AXEnhancedUserInterface` for **any** app that lists it in full context (§1.9).
5. "flips a global VoiceOver preference so that apps which check it expose their trees": only for Excel, Music, Atlas, Arc and Dia; never for Chrome, Chromium, Electron or AppKit apps (§1.9). The owner's decision the spec defers to M0 is moot for the scene families.
6. "40 levels (the vendor's `Max depth exceeded`), a node budget of 4,000": the vendor walks 200 levels silently, has no node budget, caps width at 100 children (visible subset beyond, omitted above 499), and `Max depth exceeded` is debug text; its 4,000 is the URL-character budget (§1.5, §2.5).

**Indexes and handles**
7. "an element whose handle is equal (`CFEqual`) to one already in the lineage keeps its index": matching is against the previous revision only, sibling list by sibling list under matched parents; a moved or once-absent element gets a new ID (§3.2).
8. "a vanished element's index is retired, never reused in that lineage": IDs above the surviving maximum are reused (§3.3).
9. "re-fetches by walking the current tree for the one element matching the stored identification (role, identifier, title, its path of child positions, its owning pid)": the vendor re-fetches only after `layoutChanged`/`uiElementDestroyed`, matches eleven attributes with no path or pid, and tests ambiguity before and after (§3.5–3.6).
10. "refuses … an index from another lineage … This is the vendor's observable behaviour": the vendor has no lineage check on actions (§3.3); the check is cua's addition. And `disableDiff: true` resets the vendor's lineage and renumbers from 0 (§3.4), which a service-side diff that keeps the engine's lineage will not reproduce unless it is made to.

**Input**
11. "events created from a private event source, `CGEventSourceCreate(.privateState)`, so they never count as the user's input": keyboard, scroll and modifier events use the **HID-system** source state (1); mouse events are `NSEvent`-made with no source (§5.3, §6.2). Whether pid-posted events reset the HID idle time is a run-time question the spike must answer.
12. "The event's location is the window point; the window number field is set": the location is the global point; the window point goes through `CGEventSetWindowLocation`, and the window id into fields 91/92 (§5.3).
13. Route 3, "the SkyLight posting function that carries a window-local authentication field, together with the active-state events … for the duration of the click": no SkyLight post exists in the binary (§11); the vendor's ordinary background click is a `CGEventPostToPid` with **⌘ added to the flags** when the app is not active, and the fake-activation events are reserved for held keys or flags, web views, `clickingMayCauseSelection`, Catalyst, keyboard actions and menu-bar items, with the believed-active state lasting until `deactivateFocusEnforcer` (§5.4–5.5).
14. "`AXPress` for a single left click, `AXShowMenu` for a right click, `AXIncrement`/`AXDecrement`": the vendor prefers `AXPick` over `AXPress`, never uses `AXShowMenu`, and synthesizes every right click (§5.1).
15. Keys: "the vendor's xdotool-style grammar with aliases (`super`, `Control`/`Ctrl`, `Alt`, `Shift`, …) parsed into virtual key codes through the current keyboard layout": names are exact and case-sensitive (`Control`, `Ctrl`, `Alt`, `Shift`, `Enter`, `Esc` do not exist), and key codes come from a fixed ANSI table, not the layout (§6.3–6.4).
16. Text: "a character the layout cannot key … goes as a Unicode-string event with key code 0, in chunks of at most 20 UTF-16 units": the vendor sends one key press per UTF-16 unit with key code and Unicode string together, 250 µs apart, unchunked, and **drops** units with no key code (§6.2). cua's fallback is a deliberate departure; the drop is what the matrix must beat.
17. Paste: "HTML as `public.html` plus plain; Markdown converted to HTML plus plain … always with the `org.nspasteboard.ConcealedType` and `org.nspasteboard.TransientType` marker types": the vendor also writes `public.rtf`, its plain text is the rendered attributed string, it writes no marker types (it uses `NSPasteboardContentsCurrentHostOnly`), and the 2 s read wait is followed by a 2 s effect poll under the same sentence (§7.2, 7.4–7.5). The markers are cua's addition and must not be cited as the vendor's mechanism.

**Settle**
18. "For the action's duration and after it, an `AXObserver` … `kAXValueChangedNotification` … `kAXDrawerCreatedNotification` … `kAXMenuClosedNotification`": the observer exists only after the action, listens to ten notifications without `valueChanged`, `drawerCreated` or `menuClosed`, and adds `focusedWindowChanged`, `elementBusyChanged` and `created` (§8.2).
19. "returns 150 ms after the last one … If none arrives within 1 s of the action, the engine returns at 1 s: that is the vendor's floor": the quiet period is 250 ms sampled every 0.1 s (0.25 s for web-shaped apps), there is no 1 s floor (about 0.3 s with nothing posted), the 5 s cap is silent, a windowless app always runs to the cap, and on cua's IPC path the settle happens at the next `get_app_state`, not inside the action (§8.1, 8.3, 8.6).
20. "extended while a progress indicator or busy element is present": busy means `AXBusyIndicator`, an `AXWebArea` with `AXLoaded` false, `AXElementBusy`, or the `macos-mac-parity-spinner` DOM class; `AXProgressIndicator` is not a sign (§8.4).

**The service**
21. Renderer: "whether an `App=` line precedes it is settled by M0's first real capture": the two producers of the IPC text emit no `App=` line (§2.6).
22. Diff: "the vendor's four headers": only the "previous" header with its two legends is reachable; the cumulative header is dead; the legend is fixed by a flag defaulting to true, not by the removed list's length (§4.1–4.2). "a screenshot-only observation advances the baseline": every observation does, there is no screenshot-only mode in the helper (§4.8).

**User intervention**
23. "Physical input is the machine-wide HID idle time … No event tap and no Input Monitoring permission are needed": the vendor uses a listen-only `CGEventTap` at `kCGAnnotatedSessionEventTap` on five event types, filtered by source pid (§9.2). cua's HID-idle design is its own choice, not the vendor's evidence.
24. "Given physical input during the sequence, the sequence stops and fails with `userIntervened`": the vendor never stops an action in flight; "The user changed…" is the next request's refusal, raised after waiting out the debounce (§9.5).
25. "the vendor's 'still interacting' refusal when the user touched input within a debounce … the vendor refuses before posting anything": within the debounce the vendor waits up to 100 s and then proceeds; "still interacting" appears only after 100 s of continuous input (§9.5).
26. "when the driven app is frontmost at the moment of that input … a background driven app is exempt": no frontmost test exists; attribution is per event by window owner or target pid, so a click on the driven app's background window counts and typing into the user's window does not (§9.3).
27. "1 s is cua's value until `F` recovers the vendor's `userInteractionDebounceDuration`": 5 s, and the printed number is a literal 5 (§9.1, 9.5).
