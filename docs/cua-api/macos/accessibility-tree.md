When a window holds more than its accessibility tree can list, the tree lists what the window shows first, in its usual order, and ends with a line such as `[truncated: at least 1234 elements omitted, above and below the visible area]`, the count a lower bound and the words saying which way the omitted elements lie. To reach an element the tree does not list, scroll toward it and call `getAXState()` again. A visible control inside a container that reports a collapsed frame can still be left out. In a Chromium-based app, a table's column and header elements take new element IDs at every observation. When the app's window lies outside every display or on another Space, the tree says so in a line such as `[window off screen: …]`, the window may show no content, and `getScreenshot()` fails naming the reason; ask the user to move it onto a display, or to bring it here or switch to its Space. Some apps' windows on another Space make observing the app fail with `windowOnAnotherSpace` instead, and a window's Raise action fails the same way there, with nothing sent.
