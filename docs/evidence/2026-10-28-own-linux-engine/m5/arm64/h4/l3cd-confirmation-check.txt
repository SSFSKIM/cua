## What the engine's activate_window confirms (native/linux-engine/src/engine/windows.rs:21-47)
It sends _NET_ACTIVE_WINDOW (source 1), a raise and SetInputFocus together, checks each request's reply, then
`wait_until(|| self.x.on_top(window), ON_TOP_WAIT, ON_TOP_POLL)`: it waits only until no normal-layer window covers the
window's visible area (stacking), at most 1000 ms, and answers. It never reads _NET_ACTIVE_WINDOW back, and focus_ack is
not on this path. The wait's length goes to `extra["activation"].on_top_wait_ms`, which reaches only a `--stats` line;
these counted runs had no --stats, so the rows carry no engine-side confirmation time.

## What the rows do carry, per late run
answered = answered_ms (the request's own time, harness side); request seen = the witness's sighting of the engine's
_NET_ACTIVE_WINDOW ClientMessage (`activations[].t_ms`, from the span's start; this is the request, not a confirmation);
after-read = the harness's reading after the answer and the 10 ms settle (waited_ms), read_ms long: the application's
AT-SPI ACTIVE state (`active`) and the root's _NET_ACTIVE_WINDOW (`wm`, true when it names the target); late_ms = when the
harness's 50 ms poll first saw wm true, from the answer.
