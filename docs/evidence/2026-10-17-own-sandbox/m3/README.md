## Default mode denies run/, and the review fixes (`fedc016/`)

**The constraint, at 83086188.** bubblewrap itself could mount over `run/` and bind `run/<id>` back read-only; the helper does not. `codex-rs/linux-sandbox/src/bwrap.rs` `create_filesystem_args` (its mount-order comment, lines 414-430, and the code at 566-612, 627-669 and 790-800): readable roots are bound first (`--ro-bind / /` for a policy that reads `/`), then the unreadable ancestors of *writable* roots are masked and only the writable roots are re-bound inside them (`--bind`), and every other unreadable root is masked last. A read entry inside a denied directory is never re-bound, so under default, where nothing is writable, a denied `run/` hides the session's own `run/<id>` too (the kernel could not `chdir` into its cwd, so the first M3 shape left `run/` out under default).

**What the default-mode kernel needs from `run/<id>`.** Two things, both movable: its working directory (`process.chdir(--working-dir)` at start, `src/repl-host/kernel.mjs:196`; then only a module search base and a name for cell identifiers, nothing written under default) and its lifeline FIFO, which the supervisor makes under the child's TMPDIR (`src/repl-host/kernel-child.mjs` `lifelinePipe`) and the kernel must open to start. Its stdio FIFOs are opened by the supervisor and passed as descriptors. Nothing else: TMPDIR is not writable under default, and the trusted worker, which keeps `run/<id>`, is not denied `run/`.

**The shape (`2c8abf6`).** The deny list is the same in every confined mode, `run/` included. On Linux under default the launch names the kernel's own directory outside `run/`, `$CUA_HOME/kernel/<session>/` with `tmp/` (`CUA_REPL_KERNEL_DIR`; created 0700 with the session, removed with it by release and the stale sweep); the supervisor starts the kernel there, its TMPDIR (and so its lifeline) that `tmp/`. Another session's `kernel/<id>` holds nothing but a lifeline FIFO while its kernel starts.
