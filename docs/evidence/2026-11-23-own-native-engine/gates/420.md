# Gate #420: type_text and a character outside the BMP in Chromium apps

- **Ticket:** [#420](https://github.com/SSFSKIM/cua/issues/420), "macOS engine: type_text drops a non-BMP character
  (an emoji) in Chromium-based apps" (P2). Gate of the macOS default switch (M5 pre-flight §6), task T8a.
- **State:** fixed and unit-proven, for both kinds of text:
  - non-secret text takes the paste route;
  - secret text is refused before any key (ruling 1128).

  Neither runner witness has run. **Open.**

## What the record shows

- **Password fields drop it.** #414's hosted qualification (`docs/evidence/2026-11-18-secure-type-confirm/`; kit
  `probe/414-qual` at b7aebd311c0c0edffd113a710425aad2c4c12bad, `scripts/probe-414/README.md`) typed ASCII with one
  non-BMP scalar as **concealed** requests into password fields. The text was exact 0 of 20 on Chrome for Testing 157
  and on both Electron 44 lanes, on main and on the fix alike. The shape diagnostic
  ([run 44353014580](https://github.com/SSFSKIM/cua/actions/runs/44353014580)) showed only the scalar missing, 5 of 5.
  Safari and AppKit got it exactly, 20 of 20.
- **Plain fields did not drop it in October.** In M2b's hold 3 on the mini (an older Chrome), cua's keyed rows
  `chrome/latin/typeText.emoji` and `electron/latin/typeText.emoji` were exact in both runs, as were the `acceptance4`
  rows. Nobody has measured plain Chromium fields on a runner since.
- **The vendor drops it everywhere.** Hold 3's vendor lane read length 1 of 6 on every emoji row: it keys through the
  layout and drops what the layout cannot key, answering ok.
- **The paste route works in Chromium.** #361's qualification measured it on Chrome for Testing and Electron, in the
  background, 480 of 480 exact pastes confirmed (`docs/evidence/2026-11-18-paste-readback/`).

## The fix

The test is the same for both kinds of text: is the app Chromium-family, and does the text hold a scalar above
U+FFFF? Chromium-family means Info.plist's principal class is `BrowserCrApplication` or `AtomApplication`, the engine's
existing `chromiumFamily`. The engine cannot tell before typing which Chromium fields drop the scalar, so every such
text counts, whatever the field.

- **Non-secret text** takes the paste route, under a reliable Latin source too. The pasteboard is saved and restored
  around it, and the answer reports `cua/inputRoute: "paste"`. BMP text (Hangul, CJK, combining marks), other apps
  (Safari, AppKit, Firefox) and the spike's `spikeKeyed` override keep their route.
  - Commit f129d26206b293ef5a8eeacdfb6cf4c439523059.
- **Secret (concealed) text** is refused before the first key and before any pasteboard write (ruling 1128). A secret
  is never pasted, and typing it would enter it partly.
  - The refusal is `concealedInputUnavailable`. Its meta's interval is null, which is how the service and the wrapper
    know nothing was entered. Its cause is in the meta: `concealedRefusal: "droppedCharacter"`. The input source's
    refusal now carries `"inputSource"`.
  - The engine's sentence: "Nothing was entered: the secret holds a character this app drops when typed, such as an
    emoji, and cua will not type it partly or paste it. Use set_value on a settable element instead."
  - The wrapper (`src/services/secret-input.mjs`, `CONCEALED_REASON`) picks its fixed sentence by that cause: "…was
    refused and nothing was entered: it holds a character this app drops when typed, such as an emoji, and cua never
    types a secret partly or pastes it. Use setValue on a settable field, which needs no keystrokes or clipboard".
  - It names the input source only when that is the cause. A refusal with no cause field also names the source: only
    engines from before ruling 1128 send none, and they refused a `type_text` only for the source. A cause it does not
    know names none.
  - Neither sentence carries a character, a position or a length.
  - The dropped character is the cause named even under an unreliable reading, since no input source would type it.
  - A BMP secret is typed as before.
  - Commit 7e948e006d2a5824f938bbcbdf2d81c5c5c0b361. Files: `native/engine/Sources/Engine/Routes.swift`
    (`ConcealedRefusal`, `typedTextRoute`, `concealedCharacterDropped`), `native/engine/Sources/Engine/Input.swift`
    (the meta's `concealedRefusal`, `typeText`), `src/services/secret-input.mjs`, `src/services/sky.mjs`, and the
    tests.

Both commits ride on `engineVersion` 0.2.0.

## Declared departure (R3)

**Row:** a secret (concealed `type_text`) holding a character above U+FFFF, in a Chromium or Electron app.

| | Answer |
|---|---|
| Vendor | Keys through the layout, drops what it cannot key, and answers **ok** with the secret partly entered |
| cua | Refuses as `concealedInputUnavailable` before any key: nothing entered, nothing posted, the pasteboard untouched |

- **Decision Log entry:** ruling 1128 (2026-11-23), in the spec's Decision Log entry for #186, #190 and #420 and in the
  execution record `docs/doperpowers/specs/2026-10-18-own-native-engine-m5-wave1.md`.
- **Kind:** cua refuses where the vendor answered ok, the only kind R3 lets anyone declare. It goes on the owner's page
  under "what changes for a user".
- **What the declaration needs.** It stands only on an **observed pair**: the vendor's ok and cua's refusal, each from a
  valid sample of the same cell, with the row's own effect and interference checks on both sides (pre-flight §7, "No
  valid pair, no verdict"). A declaration cannot supply an answer nobody observed. A missing or invalid sample on
  either side is NO VERDICT, and it cannot close the gate.
- **Where the pair comes from.** It comes from a vendor-service lane that T10 builds once H0's vendor witness answers.
  That lane runs the same fixture and the same synthetic trial as the qualification kit below. The paired result is
  attested apart from the kit's cua-only qualification score, and never pooled with it. If H0 fails for the vendor,
  this pair follows ruling 1116's options like every other vendor comparison. Until it is observed, the declaration is
  NO VERDICT.

## Unit witness

`native/engine/Tests/EngineTests/RouteTests.swift`:

- **`testATextTheKeysWouldDropTakesThePasteRoute`:**
  - the predicate for an emoji, and for a non-emoji scalar above U+FFFF, in a Chromium app;
  - not for other apps, BMP text or empty text;
  - non-secret text takes `.paste` under reliable and unreliable readings;
  - the spike override still keys.
- **`testAConcealedTextTheKeysWouldDropIsRefusedForThatCause`:** `.refusedConcealed(.droppedCharacter)` under every
  reading and override. This replaces the earlier assertion that such a secret stays `.keyed`.
- **`testASecretTheAppWouldDropIsRefusedBeforeAnythingIsPostedInChromeAndElectron`:** through `typedTextRoute`, with
  Info.plists for Chrome (`BrowserCrApplication`), Electron (`AtomApplication`), Safari and an AppKit app.
  - Chrome and Electron refuse, with the meta's `startedAt`, `endedAt` and `entered` all nil (nothing posted),
    `concealedRefusal` set to `droppedCharacter`, and a message free of the input source and of any part of the secret
    or its length.
  - A BMP secret is keyed there.
  - Safari and AppKit key the same secret.
- **`testTheInputSourceRefusalNamesItsCauseInTheMeta`:** a Korean-source refusal carries `concealedRefusal` set to
  `inputSource`.

The unit test cannot count posted events, because `typedTextRoute` decides before any posting code runs. It shows
the meta's interval null, the engine's own "nothing posted" signal. The runner witness counts the keys.

`test/services-sky.test.mjs`, "cua's engine-only error names are admitted value-free…":

- the `droppedCharacter` sentence, with no "input source";
- `inputSource`, no cause and a null meta all give the source sentence;
- an unknown cause blames nothing;
- a concealed paste keeps its own sentence;
- every refusal is value-free.

Results:

- **Before:** the Swift tests did not compile (`enum case 'refusedConcealed' has no associated values`). The wrapper
  test failed with the source sentence on the `droppedCharacter` refusal.
- **After:** `swift test --filter 'KeyRouteTests|…'`, 0 failures. `node --test test/services-sky.test.mjs
  test/services-engine-service.test.mjs`: 75 tests, 75 pass.
- The whole Swift suite and the focused node tests at the end of the fix wave: the task report
  (`.doperpowers/sde/2026-10-18-own-native-engine-m5-wave1/task-2-report.md`, "Fix wave").

### A. #420's own check: the qualification kit

The ticket's check, adjusted by ruling 1128, run with the kit that measured the defect.

**The cells.** Per lane, per head, 20 repetitions of each. The text is the #414 kit's own non-BMP input:
`materialize({kind: 'unicode'})`, four ASCII characters, U+1F4A1, then three ASCII characters.

| Cell | Chromium lanes (CfT, Electron default, Electron parity): fix must | Safari, AppKit, Firefox (controls): fix must |
|---|---|---|
| Non-secret into the **plain** field (`#setup`, the fixture's `Setup control`) | Exact 20/20, `inputRoute` `paste` | Exact 20/20 keyed (`2'`), as on main |
| Non-secret into the **password** field | Exact 20/20, `inputRoute` `paste` | Exact 20/20 keyed (Firefox: delivery exact; its read-back is #419's documented `notTextField`) |
| **Secret** (concealed) into the **password** field | **Refused before any key, 0 keys posted**: `concealed_input_unavailable` from the wrapper; native meta `startedAt`/`endedAt` null and `concealedRefusal` `droppedCharacter`; the page's trusted `keydown` and `input` flags false; the field empty; the pasteboard's change count unchanged | Exact 20/20 keyed, length-confirmed as in #414 (Firefox uncovered, #419) |

The main head runs the same cells. On it the Chromium cells are expected to miss (the defect) and the controls to be
exact. That shows the kit detects the defect, and that the controls do not regress.

**The kit.** A disposable `probe/420-qual` branch cut from `origin/probe/414-qual` at b7aebd311c0c. It keeps that
kit's workflow, lanes, hosted guards, owned fixtures, isolated homes and privacy scanner, and changes:

1. **`scripts/probe-414/check.mjs`: the plan.** Add `plan420()`: per rep 0–19, per head (alternating order, as
   `plan()` does), the three cells above as `{kind: 'unicode', field: 'plain'|'password', literal: true|false}`.
2. **`scripts/probe-414/run.mjs`: the mode and the cell's field.**
   - Add mode `nonbmp-420`, accepted on all six lanes.
   - A cell's `field` picks the target. The password field is the kit's existing target. The plain field is the
     fixtures' `setup` control: `page.mjs`'s `<input id="setup" type="text">`, which the probe-390 Electron fixture
     serves too, and `fixture.swift`'s `NSTextField` "Setup control".
   - The plain field's read-back is **not** the existing `setupExact`. That one compares the field with `setupText`,
     and `page.mjs`'s `prepare` writes `setupText` into the field (`setup.value=c.setupText??''`), so a seeded field
     would pass without anything being typed. The plain cells never set `setupText`; they read through the new fields
     in 3.
   - `nonBmpShape` profiles a miss on either field.
   - A concealed Chromium row is valid only with the refusal's fields above. `startedAt`/`endedAt` are already
     allowlisted raw-meta fields. `concealedRefusal` is a fixed word and is added to the privacy scanner's allowlist.
3. **A pre-action check separate from the read-back, so a cell passes only by delivered text.** Both live in
   `page.mjs`'s `state()` and `fixture.swift`'s `command(_:)` reply.
   - **Before the type call:** the `prepare` reply must show the target field empty and focused.
     - Plain field: `plainEmpty` (`setup.value===''`; AppKit: the field editor's string, else `stringValue`, is empty)
       and the existing `plainFocused`.
     - Password field: the existing `focused`, and `exact` against `''`.

     A row whose pre-check fails is setup-invalid, never scored.
   - **After the type call:** a separate `op: 'read'` compares the target with `plainExpected`, a field of the read
     command only, never of `prepare` or `seed`. Page: `plainExact: setup.value===c.plainExpected`. AppKit: `plainExact`
     against `setup.currentEditor()?.string ?? setup.stringValue`.
   - **AppKit has no setup read-back today.** At b7aebd311, `fixture.swift`'s reply carries `plainFocused` but no
     `setupExact` or any plain read-back, so `plainEmpty` and `plainExact` are new there.
   - **Trusted-event flags on the plain field.** Add `plainKey` and `plainInput`, the same trusted flags the password
     field has: page `keydown`/`input` listeners on `#setup`; AppKit, the local `keyDown` monitor counting when the
     first responder is the setup field's editor.
   - **Scoring.**
     - A non-secret control passes only if the pre-check held, `plainExact` (or the password field's `exact`) is true
       after, and `plainInput` (or `input`) is true.
     - The secret cell passes only if the pre-check held, the field is still empty after, and both the key and input
       flags are false.
   - **The pasteboard.** Read `NSPasteboard.general.changeCount` before and after each concealed row, through
     `host.swift`'s existing command channel.
4. **Firefox's shape.** At b7aebd311, `runShape` (`check.mjs`) makes Firefox password-only (`singlePassword`) in every
   mode but `firefox-focus`, so its page has no `#setup` field. The reason is #419: with a setup field, Firefox's
   focus reads the setup field, not the password. The override:
   - `runShape(lane, mode, field)` gives `singlePassword: lane==='firefox' && !(mode==='nonbmp-420' && field==='plain')`.
   - Firefox runs as two jobs, each starting its own page: phase `stock` (password-only, the password cells) and phase
     `plain` (with-setup, the plain cells).
   - On the plain page the plain field is the target, so #419's misread focus is the intended one.
   - The config's `fixtureShape` records which shape each job ran.
5. **`.github/workflows/probe-414-qual.yml`.**
   - Rename it `probe-420-qual.yml`, with its `push` registration path.
   - Add `nonbmp-420` to `mode`. Its matrix is the five stock lanes (cft, electron, electron-parity, safari, appkit,
     each phase `stock`) plus firefox's `stock` and `plain`.
   - Gate the run: fix 20/20 on every scored cell above, 0 wrong successes, 0 privacy flags, 0 setup-invalid rows.
